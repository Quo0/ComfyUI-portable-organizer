# 工作流库

工作流存在每个整合包内部的 `user\default\workflows\` 里，不会在整合包之间
流动。工作流库是所有整合包之外的一个文件夹，放你真正在用的工作流，带标签、
备注和收藏。

在 **设置 → 工作流库** 里指定这个文件夹。应用会建议把它放在共享模型文件夹
旁边，但两者之间没有硬性关联：没有共享模型，库也能用，反过来也一样。

## 库是一个文件夹，不是数据库

```
<库>\
├─ _library.json      清单：标签、备注、收藏
├─ sdxl\
│  └─ base.json
└─ upscale.json
```

清单放在**库文件夹内部**，而不是应用的数据目录里，所以这个库自成一体：
重装应用后它还在，搬到另一台机器上也只是搬一个文件夹。

在资源管理器里编辑这个文件夹不会弄坏任何东西。清单里没有记录的文件是合法
的，照原样显示；记录对应的文件不见了，会被标为已丢失，并提供删除这条记录
的选项。文件才是事实，清单只是给它们加点信息。

## 怎么往里放

- **添加文件**，以及把 `.json` 拖放到库页面上。
- **丢一张 ComfyUI 生成的 PNG 进来**：工作流就藏在图片内部的 `workflow`
  文本块里，应用会把它取出来。想回到某次满意的生成，通常就是从那张图
  开始的。
- **以文本粘贴。** 在聊天和论坛里，工作流以文本形式分享的时候比文件多。
  粘贴表单会自己读剪贴板，边输入边解析，并在保存前显示节点数量——这是不用
  读两千行就能确认粘对了东西的唯一办法。名字会当场就问，并且会校验：它会
  变成一个路径。
- **从整合包取入**——在整合包的**工作流**标签页里。

## 取入是移动，不是复制

把工作流从整合包取进库里，会把它从整合包中移走。顺序和模型那边一样，理由
也一样：先写副本，再读回来比对，然后才删除原件——如果整合包正在运行，就
通过 ComfyUI 自己的 API 来删，好让它知道自己的文件夹变了。

**完全没有覆盖这回事。** 名字被占用时，靠比对内容来解决，而不是问你要不要
替换：

- 完全相同 → 没什么可取的，按钮是灰的；
- 内容不同 → 这是两份工作，整合包里的那一份会在询问之后，以一个空闲的
  名字取入（`base.json` → `base (2).json`）。

替换会把一份工作碾在另一份下面，最后两份都留不住。

比对先看字节，再看解析后的 JSON。第二步不是可有可无的：ComfyUI 每次保存都
会重写文件，没有这一步，几乎每个已经取入过的工作流都会被判定为不同。

## 把工作流添加到整合包

- **运行中的整合包** → 通过它的 API 上传，带 `overwrite=false`。ComfyUI
  返回的 409 会变成一个提问——覆盖，还是换个名字保存——而绝不会是悄悄替换。
- **已停止的整合包** → 复制到 `user\default\workflows\`。如果配置里有
  `--user-directory`，路径就从它推导，而不是想当然。

运行中的 ComfyUI 里的列表，会在它的页面刷新时一起更新。

批量操作两个方向都支持：多个工作流放进一个整合包，一个工作流放进多个
整合包。

## 缺少节点的提醒

这正是这个功能待在这里、而不是待在资源管理器里的理由。应用从工作流的 JSON
里取出节点类型，和某个整合包实际拥有的做比对：

- **运行中的整合包** —— 当场直接问它。
- **已停止的整合包** —— 和它上次成功启动时留下的快照比对，并如实标注。
- **在我们眼皮底下从未启动过** —— *未知*，就按未知显示。背后什么都没有的
  绿色对勾，比没有对勾更糟。

这是提醒，不是拦截。安装缺少的节点是 ComfyUI-Manager 的活儿；应用只告诉你
该找什么。

## 它有意不做的事

不编辑工作流，不做画布预览，不做版本管理，也不安装缺少的节点。

两条被否掉的捷径，万一你正打算自己动手：用 `--user-directory` 共享整个
`user\` 目录，会连前端设置和扩展状态一起共享，而它们在节点集合不同的整合包
之间是冲突的——这正是分开存放整合包要避免的问题。在 `workflows` 文件夹上做
一个 junction，则意味着改一个工作流会悄悄改到所有地方，删一次文件夹就是
替所有人删掉。
