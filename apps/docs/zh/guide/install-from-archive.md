# 从压缩包安装

`ComfyUI_windows_portable_nvidia.7z` 需要你自己从 ComfyUI 项目下载。应用
负责解压它——解到一个位置，或者一次解到好几个——登记结果，并且可以在同一
轮里把它们连接到你的共享文件夹。

它在 **添加 → 从压缩包解压**，是一个常驻的部分，不是首次启动的某个步骤：
在旧版本旁边铺开一个新 ComfyUI 版本，走的也是这条路。

## 步骤

1. **压缩包。** 选一个 `.7z`，或者从历史记录里挑一个用过的。使用之前，
   应用会检查文件是否还在、大小和修改时间是否没变——压缩包是会被删掉和
   替换的。
2. **读取。** 从头部解析出条目数量、解压后的总大小，以及里面唯一的根
   目录。一个 2 GB、含 56 000 个条目的压缩包，这一步大约花一秒，界面上
   会这么写。
3. **目标位置。** 一个或多个。每个都有自己的路径、名称、说明和标识颜色。
   应用会检查文件夹是空的或不存在、空间是否够用、路径是不是长得危险。
4. **共享资源。** 可选（但强烈建议）的开关，用于
   [共享模型文件夹](/zh/guide/shared-models)和
   [工作流库](/zh/guide/workflows)。
5. **解压**，然后 **完成**，新整合包已经可以启动。

## 目标路径请选短的

压缩包里最深的文件，大约在根目录以下 206 个字符处。Windows 传统的路径
上限是 260，所以 `D:\AI\comfy-sdxl` 这样的目标很宽裕，而
`C:\Users\你\Documents\AI 相关\ComfyUI 整合包\实验\sdxl` 就不是。

路径过长时应用会提醒。它解压时走的是 `\\?\` 前缀的原义路径，能撑得比
资源管理器更远，但你之后要用的工具——包括 ComfyUI 自己的自定义节点安装
程序——未必撑得住。

## 一次解到多个位置

解压只做**一次**。第二个及后面的目标是从第一个复制过去的，因为解压吃
CPU，而复制一棵现成的目录树吃磁盘。有两三个目标时，这能省下好几分钟。

## 中断是安全的

文件先进入临时文件夹 `<目标>.cpo-partial`，只有解压完成后才移到位。这不是
装饰：解压到一半的目录树里已经有了 `python_embeded\python.exe` 和
`ComfyUI\main.py`，也就是说它能通过应用自己的有效性检查，看上去像个能用
的整合包。

取消——或者崩溃——都会删掉那个临时文件夹。清理几万个文件要花些时间，因此
它作为一个独立阶段被报告出来，免得被取消的安装看起来像卡死了。

## 可用空间

在动手之前就根据压缩包头部检查过了，留有余量，并按落在同一个卷上的目标
数量相乘。二十个 GB 的解压走到第十九个才发现空间不够，是最糟糕的时机。
