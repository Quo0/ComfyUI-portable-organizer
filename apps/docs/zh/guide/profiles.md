# 启动配置

一个配置就是启动某个整合包的一种方式。便携版自带的 `.bat` 文件会自动变成
配置，`advanced\` 里的也不例外。

## `.bat` 文件是被读取的，不是被执行的

那些文件只有一行：

```bat
.\python_embeded\python.exe -s ComfyUI\main.py --windows-standalone-build --fast fp16_accumulation
```

应用解析这一行，然后直接启动 `python.exe`。于是有两样东西消失了：文件
末尾的 `pause`，它本来会停在那里等你按回车；以及进程树里多出来的那个
`cmd.exe`，它会让停止服务器变得不那么可靠。

相对路径以 `.bat` 文件自己所在的目录为基准——双击它时就是这么解析的，而
`advanced\*.bat` 里带 `..\` 的路径正是靠这一点。

**你的 `.bat` 文件永远不会被改动。** 每次启动都会重新读取它们，所以你对
它们的修改也会立刻生效。

如果某个文件解析不了，配置会退回到用 `cmd /c` 运行，并在界面上如实标注。
这样的进程停起来不太可靠，在依赖它之前你应该先知道这件事。

## 应用往命令行里加了什么

三个参数，启动前可以在启动参数编辑器里看到最终的完整命令：

| 参数 | 为什么 |
| --- | --- |
| `--port <n>` | 端口由应用分配。配置里原有的 `--port` 会连同它的值一起被移除。 |
| `--disable-auto-launch` | 免得弹出浏览器标签页。ComfyUI 在 `--windows-standalone-build` 之后才处理这个参数，所以它总是胜出。 |
| `--extra-model-paths-config <路径>` | 仅当整合包以参数模式连接到[共享模型文件夹](/zh/guide/shared-models)时。 |

`.bat` 里原本就有的 `--extra-model-paths-config` 不会被动：这个参数是可以
累加的，我们的那份是加在你的旁边，而不是取代它。

## 你自己的配置

**整合包的设置 → 参数** 允许你在解析出来的配置之上做一份自己的：改动参数，
以你喜欢的名字保存。原件保持原样，因为它们是别人安装目录里的文件。

编辑器会显示最终的命令行——真正交给 Windows 的那一条，我们的参数已经加好
了。跟一条看不见的命令行较劲，没什么乐趣。

## 哪个配置会启动

**启动** 是个组合按钮：主体那一半启动你上次为该整合包用过的配置，箭头
打开列表。不会拉起服务器的配置——也就是包里自带的更新脚本——已经从列表里
滤掉了，因为它们不是启动。

## 启动日志

进程写到 stdout 和 stderr 的一切，都从第一行起实时传到应用里。`tqdm` 的
进度条会覆盖自己那一行，而不是灌满缓冲区，和在终端里的表现一样。日志保留
大约 5000 行。

整合包启动期间，应用会轮询 `GET /system_stats`，直到服务器响应，然后把
日志换成 ComfyUI 标签页。大整合包的冷启动要花几分钟；超时是五分钟。
