# 已知限制

那些没人明说出来、就会让你意外的事情。

## 两个整合包共用一张显卡

同时跑两个整合包，没什么能拦着你，应用在放行之前也会问一句。但显存不会
被均分：第二个整合包把自己的模型加载到同一张显卡上，然后在生成队列里失败，
报错却完全说不到真正的原因。两张显卡，或者用 CPU 配置，才是“仍然启动”
说得通的场合。

## ComfyUI-Manager 会在我们背后重启服务器

安装完自定义节点后，ComfyUI-Manager 会杀掉服务器并拉起一个新进程。我们对
它的句柄失效了，于是整合包显示为**不受控制**：活着，但已经不归我们停止。
应用会提供重新连接——它找到占用该端口的进程，把它接管回来。参见
[端口与冲突](/zh/guide/ports#当-comfyui-自行重启)。

## 关闭应用会停掉所有服务器

ComfyUI 进程是应用的子进程，被放在一个作业对象里，应用退出时会把它们一起
带走。这是有意的——一个占着你显存的孤儿 `python.exe` 更糟——但这也意味着，
只要还有东西在跑，关闭窗口按钮就会问你一句，安装更新时也一样。

如果你希望服务器继续工作，那就最小化到托盘。

## ComfyUI 标签页是一个原生窗口

它不是 iframe。这一点有肉眼可见的后果：我们的任何东西都画不到那个矩形
上面，所以设置、启动参数编辑器和所有确认都是独立页面而不是对话框，消息也
是以横幅形式出现在标签页**上方**，而不是浮在它之上的提示条。

标签页内部的下载和“保存图像”由 WebView2 处理，不归我们管——它们的表现和在
Edge 里一样。

## 长路径

便携版整合包里最深的文件大约在根目录以下 206 个字符处，而 Windows 传统的
上限是 260。应用解压时走原义路径，能撑得比资源管理器更远，但你之后运行的
工具——包括自定义节点的安装程序——未必撑得住。目标路径请保持简短：
`D:\AI\comfy-sdxl`，而不是你用户目录里往下五层的某个文件夹。

## 模型只比对名称和大小，不比对内容

重复报告和“共享文件夹里已有”的标记，比对的是文件名和大小。为了确认无疑而
去算一个 20 GB 大模型的哈希，每个文件要花上几分钟，而这份报告是用来看的，
不是用来等的。

重复报告从不碰任何文件——它只统计。删除是整合包“模型”标签页上一个独立且
需要明确确认的操作。

## 只支持 Windows

macOS 和 Linux 既不构建也不测试。便携版 ComfyUI 本来就是 Windows 上的
做法；在别的系统上人们用虚拟环境，这个应用要解决的问题在那里并不以同样的
形态存在。

## 没有代码签名

安装程序未签名，所以 SmartScreen 会对它发出警告。参见
[SmartScreen 提示页](/zh/guide/smartscreen)——那里也讲了如何校验文件，而
不是选择信任它。
