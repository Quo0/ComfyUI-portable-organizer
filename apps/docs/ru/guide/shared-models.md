# Общие модели

У каждой портабл-сборки свой `ComfyUI\models\`. Один чекпоинт — это
2–20 ГБ, поэтому три-четыре сборки означают сотни гигабайт одних и тех же
файлов. У ComfyUI ровно на этот случай есть механизм —
`extra_model_paths.yaml`, — и работа приложения в том, чтобы сгенерировать
корректный файл и передать его сборке.

## Как разложить папку

Выберите папку вне всех сборок, на диске, где есть место:

```
D:\AI\_shared_models\
├─ checkpoints\
├─ loras\
├─ vae\
├─ controlnet\
├─ upscale_models\
├─ embeddings\
├─ text_encoders\        (или clip\)
└─ diffusion_models\     (или unet\)
```

Затем **Настройки → Общие модели**, выберите папку — приложение её
просканирует.

**Разделы строятся по реально существующим подпапкам**, а не по жёстко
зашитому списку категорий. Это осознанно: ComfyUI добавляет типы моделей
между версиями, и замороженный в нашем коде список протух бы. Добавьте
подпапку, пересканируйте — и она появится в конфиге.

Два устаревших имени сопоставляются за вас: `unet\` предлагается под
ключом `diffusion_models`, а `clip\` — под `text_encoders`, ровно так же,
как это делает внутри себя сам ComfyUI. Устаревшая и современная папки
могут существовать обе, и обе попадут в один ключ.

Подпапки, которых приложение не знает, перечисляются отдельно, а не
выбрасываются молча, — вы увидите, что осталось за бортом.

`custom_nodes` исключается безусловно, хотя ключ допустим и встречается
в примере от самого ComfyUI. Общие кастомные ноды перечёркивают причину,
по которой ваши сборки разделены: они конфликтуют друг с другом, и одна
общая папка сломала бы их все разом.

## Ваши локальные модели никуда не деваются

Пути **добавляются**. ComfyUI дописывает дополнительные пути к тем,
которые у сборки уже есть, поэтому модели внутри сборки продолжают
работать точно так же, как раньше. Подключение папки ничего никуда
не переносит.

Переключатель **«Скачивать новые модели сюда»** управляет одним: пойдёт ли
общая папка первой в списке — а именно туда ComfyUI Manager кладёт
скачанные файлы. На поиск моделей он не влияет.

## Подключение сборки

На вкладке **Модели** у сборки есть переключатель. Включите его — и сборка
будет пользоваться общей папкой со следующего запуска. Аргументы
работающего процесса изменить нельзя, поэтому приложение прямо говорит,
что нужен перезапуск, а не делает вид, что переключатель уже сработал.

## Два способа применения

**Режим флага — по умолчанию.** Сгенерированный YAML лежит в собственной
папке данных приложения, а в командную строку при запуске добавляется
`--extra-model-paths-config <путь>`. Внутрь вашей сборки не пишется
вообще ничего. Выключить — снять галочку; один конфиг обслуживает все
сборки и правится в одном месте.

**Файл внутри сборки.** Приложение пишет
`<сборка>\ComfyUI\extra_model_paths.yaml`. Выбирайте этот режим, если
иногда запускаете сборку её `.bat`-файлом, мимо приложения: файл ComfyUI
подхватит сам.

Политика столкновений в этом режиме строгая:

- файла там нет → пишем;
- там наш файл (узнаётся по строке-маркеру в шапке) → перезаписываем;
- **там чужой файл → не трогаем.** Вы получаете экран сравнения, оригинал
  сохраняется как `extra_model_paths.yaml.bak-<метка времени>`, и файл
  заменяется только после вашего подтверждения. Альтернатива, предложенная
  на том же экране, — оставить всё как есть и перейти на режим флага.

Отключение в этом режиме убирает наш файл и возвращает резервную копию,
если она была.

## Если папки нет на месте

Внешний диск, который не подключён, ловится **до** старта сборки,
с предложением запуститься без общих моделей. Узнавать об этом
из «model not found» посреди генерации — не вариант.

## Перенос моделей в общую папку

Вкладка **Модели** у сборки показывает, что лежит внутри этой сборки и что
уже есть в общей папке под тем же именем и с тем же размером.

- **Перенести в общую папку** копирует файл, читает копию обратно,
  сверяет — и только потом удаляет оригинал. Пока копия не проверена,
  оригинал остаётся на месте.
- **Убрать дубликаты** удаляет из сборки файлы, которые уже есть в общей
  папке, — снова после проверки, что близнец действительно там.

Оба отказываются работать на запущенной сборке: ComfyUI держит эти файлы
открытыми и разрешил свои пути при старте.

Ничего никогда не удаляется без вашей просьбы, и вам заранее говорят,
что именно уйдёт.

## Как убедиться, что сработало

Самая прямая проверка вообще не касается интерфейса. При запущенной
сборке откройте
`http://127.0.0.1:<порт>/internal/folder_paths` — там перечислены все
категории с путями за ними, общая папка в том числе, а при включённом
«скачивать новые модели сюда» общий путь идёт в своём массиве первым.

Лог запуска показывает то же самое по ходу дела: ComfyUI пишет
`Adding extra search path checkpoints D:\…` для каждого подхваченного пути.
