# Профили запуска

Профиль — это содержимое одного `.bat`-файла, приведённое к виду,
из которого можно запускать напрямую. Профили заново перечитываются
с диска при каждом запуске: источник правды — сами `.bat`-файлы,
и они не изменяются никогда.

## Из чего он состоит

| Поле | Значение |
| --- | --- |
| `id` | Путь к `.bat` относительно корня сборки. По нему профиль и опознаётся: `run_nvidia_gpu.bat`, `advanced\run_nvidia_gpu_disable_api_nodes.bat`. |
| `name` | Имя файла без расширения. Не переводится. |
| `advanced` | Профиль пришёл из подпапки `advanced\`. |
| `pythonPath` | Абсолютный путь к интерпретатору, который вызывает строка. |
| `args` | Аргументы, разобранные на токены, с учётом кавычек. |
| `cwd` | Папка самого `.bat`-файла. |
| `env` | Переменные из строк `set КЛЮЧ=ЗНАЧЕНИЕ` выше команды. |
| `fallback` | Разобрать файл не удалось; он будет запущен через `cmd /c`. |

Ваши собственные профили берут у базового всё и заменяют только `args` —
см. [`instances.json`](/ru/reference/instances-json).

## Как читается файл

`echo`, `pause`, `rem` и пустые строки пропускаются. Строки
`set КЛЮЧ=ЗНАЧЕНИЕ` становятся переменными окружения. Первая настоящая
командная строка разбирается на токены с учётом кавычек, исполняемый файл
становится `pythonPath`, остальное — `args`.

Относительные пути — включая `..\` в `advanced\*.bat` — отсчитываются
от папки `.bat`-файла, потому что именно это происходит при двойном клике
по нему. Она же становится рабочим каталогом.

Профили, которые сервер не поднимают, — например скрипты обновления
из пакета, — в список запуска не попадают.

## `fallback: true`

Если строку разобрать не удалось, профиль не выбрасывается: он помечается
как запасной и запускается через `cmd /c`. Интерфейс об этом сообщает:
такой путь ставит между приложением и Python лишний `cmd.exe`, и процесс
из-за этого хуже останавливается.

## Пути, вычисленные из аргументов

Три папки приложение не угадывает, а вычисляет из аргументов — по тому же
приоритету, которым пользуется сам ComfyUI:

| Папка | Какие флаги смотрим, по порядку |
| --- | --- |
| Модели | `--base-directory`, иначе `<сборка>\ComfyUI\models` |
| Данные пользователя (здесь живут воркфлоу) | `--user-directory`, затем `--base-directory`, иначе `<сборка>\ComfyUI\user` |
| Вывод | `--output-directory`, затем `--base-directory`, иначе `<сборка>\ComfyUI\output` |

Поэтому «открыть папку вывода» и «добавить воркфлоу в остановленную
сборку» попадают куда надо даже тогда, когда ваш профиль уводит эти папки
в другое место.
