# ComfyUI Portable Organizer — план реализации

## Context

Пользователи ComfyUI держат по несколько портабл-инсталляций, потому что кастомные ноды конфликтуют между собой и обновление одной сборки ломает другую. Сейчас управление этим зоопарком — это ручной запуск `.bat` из проводника, который поднимает сервер и открывает вкладку в браузере по умолчанию. Нет ни списка инсталляций, ни контроля портов, ни видимости логов старта, ни возможности держать несколько инстансов в одном окне.

Строим десктопное приложение под Windows: реестр портабл-инсталляций, запуск любого из профилей (`run_nvidia_gpu`, `run_nvidia_gpu_fast_fp16_accumulation`, `run_cpu`, `advanced/*`), стриминг логов старта и — главное — ComfyUI открывается вкладкой **внутри** нашего окна с нашей навигацией и оболочкой, а не в браузере.

Вторая крупная функция — **общее хранилище моделей**. У зоопарка инсталляций есть прямая цена: каждая держит собственную `ComfyUI\models\`, один чекпоинт весит 2-20 ГБ, и при трёх-пяти установках счёт дублей идёт на сотни гигабайт. Приложение даёт раздел с путём до общей папки и тумблер у инстанса, который её подключает. Механизм для этого в ComfyUI уже есть — `extra_model_paths.yaml`; подробности в отдельном разделе.

Помимо приложения репозиторий содержит **сайт пользовательской документации** — отдельный пакет со своим циклом релиза и своим CI. Раскладка папок продумана заранее (см. следующий раздел), потому что перекладывать её после первого `pnpm install` дороже: пути тянутся в `tauri.conf.json`, `.gitignore` и воркфлоу.

**Репозиторий:** новый, `d:\projects\comfyui-portable-organizer`.

**Этот документ отвечает на вопрос «как».** На вопрос «что именно приложение делает с точки зрения пользователя» отвечает каталог `specs/`: акторы, функциональные требования со стабильными ID, пользовательские истории с критериями приёмки, нефункциональные требования и сквозные сценарии. Оттуда выводятся UI-дизайн, тест-кейсы и пользовательская документация; сюда ходят за техническим обоснованием. Связь между слоями — в `specs/traceability.md`.

**Этот документ — рабочий артефакт репозитория.** Чеклист ниже отмечается по мере выполнения, изменения плана коммитятся отдельно от кода, чтобы в `git log PLAN.md` была видна эволюция замысла.

## Структура репозитория

Монорепо на **pnpm workspaces**. Cargo-воркспейса в корне нет: crate ровно один и живёт целиком внутри `apps/desktop/src-tauri`.

```
comfyui-portable-organizer/
├─ apps/
│  ├─ desktop/                 @cpo/desktop — приложение
│  │  ├─ src/                  Vue-фронт
│  │  │  ├─ screens/           экраны-роуты по разделам рейла
│  │  │  ├─ components/        оболочка: NavRail, InstanceToolbar, LogConsole, SplitButton
│  │  │  ├─ stores/            Pinia: instances, processes, logs, ui
│  │  │  ├─ i18n/              настройка vue-i18n, правила плюрализации, форматы
│  │  │  ├─ locales/           en.json (источник правды), ru, zh-Hans, es
│  │  │  ├─ styles/            tokens.css, reset.css
│  │  │  ├─ bindings.ts        СГЕНЕРИРОВАННЫЕ типы команд и событий из Rust
│  │  │  ├─ router.ts
│  │  │  └─ main.ts
│  │  ├─ src-tauri/            Rust — состав файлов см. «Архитектура Rust-бэкенда»
│  │  ├─ index.html
│  │  ├─ vite.config.ts
│  │  └─ package.json
│  └─ docs/                    @cpo/docs — сайт документации (VitePress)
│     ├─ .vitepress/config.ts
│     ├─ guide/                установка, добавление инстанса, профили, порты
│     ├─ reference/            флаги запуска, формат instances.json
│     ├─ public/               скриншоты, иконка
│     └─ package.json
├─ packages/                   пусто до первой реальной общей зависимости
├─ specs/                      требования, истории, сценарии — что делает приложение
├─ design/                     палитра и образцы компонентов; отсюда берётся tokens.css
├─ tools/fixtures/             стенд разработки, в сборку приложения не входит
├─ .github/workflows/          release-desktop.yml, deploy-docs.yml
├─ PLAN.md                     этот документ
├─ pnpm-workspace.yaml
├─ package.json                только скрипты-оркестраторы, без зависимостей
└─ .gitignore
```

**Почему приложение и сайт разведены жёстко.** Сайт не должен тянуть зависимости Tauri, приложение не должно тянуть VitePress. Циклы релиза независимы: доки деплоятся на каждый коммит в `apps/docs/**`, инсталлятор собирается по тегу. Сборка сайта обязана оставаться зелёной, даже когда Rust-часть временно не компилируется — отсюда и разные воркфлоу с фильтрами по путям.

**`packages/` заведомо пустой.** Это заготовка под общий пакет, если появится настоящая общая сущность — например, JSON-схема конфига, которую читают и приложение, и валидатор примеров в доках. Заранее туда ничего не выносим: преждевременный общий пакет свяжет два независимых цикла релиза обратно.

**Корневой `package.json` — только скрипты-оркестраторы**, без зависимостей кроме общего линтера и форматтера:

| Скрипт | Что делает |
|---|---|
| `dev:desktop` | `pnpm --filter @cpo/desktop tauri dev` |
| `dev:docs` | `pnpm --filter @cpo/docs docs:dev` |
| `build:desktop` | `pnpm --filter @cpo/desktop tauri build` |
| `build:docs` | `pnpm --filter @cpo/docs docs:build` |

**`.gitignore`:** `node_modules/`, `dist/`, `apps/desktop/src-tauri/target/`, `apps/desktop/src-tauri/gen/`, `apps/docs/.vitepress/cache/`, `apps/docs/.vitepress/dist/`.

Обратите внимание: корневой папки `docs/` нет. Имя занято сайтом в `apps/docs`, и держать рядом две сущности с одним именем — прямой путь к путанице «доки для нас» и «доки для юзеров». Внутренние инженерные документы живут в корне (`PLAN.md`, при необходимости `adr/`).

## Ключевые находки из кода ComfyUI

Три факта, найденные при разведке, определяют всю архитектуру:

**1. Патчить `main.py` не нужно.** В `comfy/cli_args.py:286-290`:
```python
if args.windows_standalone_build:
    args.auto_launch = True
if args.disable_auto_launch:
    args.auto_launch = False
```
`--disable-auto-launch` применяется после и всегда побеждает. Достаточно дописать флаг к команде — браузер не откроется. Идея с копированием и правкой `main.py` отменяется полностью.

**2. Запускать `.bat` не нужно.** Все они однострочники:
```
.\python_embeded\python.exe -s ComfyUI\main.py --windows-standalone-build --fast fp16_accumulation
```
Парсим строку, дописываем свои флаги, запускаем `python.exe` напрямую. Уходит `pause` в конце (висел бы, ожидая Enter) и лишний `cmd.exe` в дереве процессов. Обратите внимание: `advanced\run_nvidia_gpu_disable_api_nodes.bat` использует пути `..\` — относительные пути резолвим от папки самого `.bat`, она же становится cwd.

**3. `<iframe>` получит 403, child webview — нет.** В `server.py:159-197` `origin_only_middleware` режет всё с `Sec-Fetch-Site: cross-site`. Навигация iframe с нашего origin на `127.0.0.1:8188` — именно cross-site. Обойти можно только флагом `--enable-cors-header`, который в `server.py:236-239` через `else` **полностью выключает** эту защиту, открывая CSRF из любого сайта в браузере юзера. Отвергаем. Child webview грузит ComfyUI как top-level навигацию (`Sec-Fetch-Site: none`) — middleware пропускает без единого дополнительного флага.

## Стек

Rust-ядро отдаёт окно с системным вебвью, а фронт для него — это `build.frontendDist` (статика) плюс `build.devUrl` (dev-сервер). Подходит что угодно, собирающееся в HTML/JS/CSS; официальные шаблоны `create-tauri-app` включают Vue, Angular, Svelte, Solid, Preact и Rust-фронты (Leptos, Yew). Берём Vue.

- **Tauri v2** + Rust. Инсталлятор ~5-10 МБ, системный WebView2. Rust нужен только для сборки — конечный пользователь ставит обычный `.exe`. Формат инсталлятора и его связь с требованием чистого удаления — в разделе «Дисциплина хранения данных».
- **Cargo feature `tauri/unstable`** — обязателен, мультивебвью пока за ним.
- **Плагины:** `store` (конфиг), `dialog` (выбор папки), `opener` (внешние ссылки), `single-instance`, `tray-icon`.
- **Целевая платформа: только Windows.** macOS и Linux не собираем и не тестируем, но платформозависимый код изолируем за трейтами — см. раздел «Кроссплатформенность».

### Фронт приложения

- **Vue 3** (`<script setup>` + TypeScript) + **Vite**.
- **Состояние: Pinia.** Четыре стора: реестр инстансов, состояния процессов, кольцевые буферы логов, `ui` (тема, язык, очередь тостов).
- **Локализация: `vue-i18n` v11**, четыре локали, `en` — источник правды. Детали в разделе «Интерфейс: тема, язык, уведомления».
- **Роутинг: `vue-router`.** Не косметика, а прямое следствие раздела «Дисциплина z-order»: дочерний webview — нативное окно поверх нашего HTML, поэтому настройки, добавление инстанса и редактор аргументов обязаны быть отдельными экранами, а не модалками. Роутер — механизм, который это обеспечивает.
- **Стили: чистый CSS**, без препроцессоров и UI-китов. Из `design/` командой `node design/build.mjs` приезжают два файла: `styles/tokens.css` с design tokens в CSS custom properties и `styles/components.css` с компонентами. Цвета не сочиняются заново при реализации, иначе дизайн и код разойдутся. Акцентный цвет инстанса пробрасывается как `--instance-accent` на корень его карточки.

  **Оба файла подключаются глобально, один раз.** `<style scoped>` остаётся только для раскладки конкретных экранов. Это осознанный выбор против привычного «каждому компоненту свой scoped-блок»: если разрезать библиотеку по SFC, она начнёт расходиться с `design/` при первой же правке, а весь смысл каталога в том, что приложение и образцы делят один файл. Имена классов узкие и предметные, поэтому глобальная область здесь не мешает — измерено: 104 класса, ни одного общеупотребительного.

  Vuetify, PrimeVue и Naive отвергнуты по той же причине z-order: они построены вокруг телепортируемых оверлеев, а оверлеи над областью контента у нас физически невозможны. Библиотека дала бы ровно тот класс компонентов, который нельзя использовать, в обмен на вес и чужую систему тем.

- **Типы Rust↔TS: `tauri-specta` + `specta`** генерируют `src/bindings.ts` из сигнатур команд и событий. Убирает ручное дублирование моделей (`LaunchProfile`, состояния процесса, строки лога) на двух языках. **Проверить на Фазе 0**; если связка не встанет на Tauri v2 с `unstable`, откатываемся на руками написанные интерфейсы в `src/types.ts` — это единственное последствие.
- **Специфика `vite.config.ts` под Tauri**, иначе ловятся неочевидные баги: `server.strictPort: true` и фиксированный порт 1420, `server.host` из `TAURI_DEV_HOST`, `clearScreen: false` (иначе Vite затирает вывод Rust-компилятора), `build.target: 'chrome105'`, `envPrefix: ['VITE_', 'TAURI_ENV_*']`.

### Сайт документации

**VitePress.** Markdown-first, тот же Vue под капотом — один ментальный контекст на весь монорепо. Встроенный локальный поиск, деплой на GitHub Pages одним воркфлоу.

### Фронтенд: границы

Фронт умышленно тонкий. Он **не** парсит `.bat`, **не** знает про порты и процессы, **не** хранит логику ретраев и таймаутов — всё это в Rust. Фронт — это роутер, три стора-зеркала бэкендового состояния, подписки на события и вызов `set_webview_bounds`.

Единственное место связи Vue-лейаута с нативным окном — bounds дочернего вебвью. Контейнер области контента получает `ResizeObserver`; на каждое изменение прямоугольника (ресайз окна, сворачивание рейла, переход по роуту) шлём `set_webview_bounds(id, x, y, w, h)`. Автолейаута у child webview нет, ресинк только вручную.

## Разработка

Работа с Tauri здесь **полностью стандартная** — ни одного обходного пути. Но у приложения есть две особенности, о которые дев-цикл спотыкается, и знать о них лучше заранее.

### Что происходит по `pnpm dev:desktop`

Сначала `beforeDevCommand` поднимает Vite на `devUrl` (`localhost:1420`), затем собирается отладочный бинарь и открывается нативное окно, которое грузит этот самый localhost. Дев-сервер такой же, как у любого Vite-приложения, просто смотрит в него не браузер, а WebView2.

| Что правим | Что происходит | Сколько ждать |
|---|---|---|
| Vue, CSS, локали | Горячая замена, как в браузере | Мгновенно |
| Rust в `src-tauri/` | CLI следит за папкой, пересобирает и перезапускает окно | Секунды на инкрементальной сборке |

Первая сборка — минуты: Cargo компилирует Tauri со всеми зависимостями. Дальше быстро. Слежку выключает `--no-watch`, когда перезапуски мешают.

**Ничего в систему не ставится.** Отладочный бинарь лежит в `src-tauri/target/debug/` и запускается оттуда; инсталлятор появляется только у `tauri build`. Ставить и удалять программу на каждой правке не нужно.

**Devtools** — правым кликом «Inspect» либо `Ctrl + Shift + I`, в отладочной сборке включены.

**pnpm не требование Tauri.** Tauri знает только `beforeDevCommand` и `devUrl`, чем ставятся зависимости — его не касается. pnpm выбран под монорепо из двух пакетов: строгие `node_modules` не дают сайту случайно импортировать зависимость, объявленную у приложения.

### Особенность 1: дев и релиз делят папку данных

`app_data_dir()` определяется bundle identifier, и отладочная сборка использует тот же, что установленная. Значит, эксперименты в разработке пишут в **тот же реестр инстансов**, которым вы пользуетесь всерьёз.

Лечится штатным механизмом: `--config` сливает конфиги по правилам JSON Merge Patch, и `identifier` в их числе. `src-tauri/tauri.dev.conf.json` с отдельным идентификатором, подмешанный в дев-скрипте, даёт дев-приложению свою папку данных.

**Делаем в Фазе 1**, вместе с реестром: пока хранить нечего — терять тоже нечего.

### Особенность 2: правка Rust убивает запущенный ComfyUI

Следствие решения из раздела про `supervise/`: процессы живут в Job Object с `KILL_ON_JOB_CLOSE`, чтобы падение приложения не оставляло python-сирот с занятой видеопамятью. Тот же механизм срабатывает при перезапуске окна после пересборки Rust.

Цена конкретная: холодный старт реальной сборки с полусотней кастомных нод — до пяти минут. Одна правка в `supervise/windows.rs` означает пять минут ожидания ради одной строчки.

**Делаем в Фазе 2**, до работы над супервизором: раньше не нужно, позже — поздно.

### Стенд

Поддельный инстанс, который выглядит для приложения настоящей портабл-сборкой, но стартует за секунду. `tools/fixtures/fake-instance/`:

```
python_embeded/     ← junction на системную установку Python
ComfyUI/
  main.py           ← заглушка сервера
  comfyui_version.py
run_nvidia_gpu.bat
run_cpu.bat
advanced/run_nvidia_gpu_disable_api_nodes.bat
```

`python_embeded` — **каталоговый junction** на системный Python: на Windows не требует прав администратора, создаётся мгновенно, не занимает места, а `python_embeded\python.exe` при этом существует и запускается. Валидация папки и запуск интерпретатора работают по-настоящему, а не в обход. Junction нельзя положить в git, поэтому фикстура создаётся скриптом.

`.bat` пишутся однострочниками того же вида, что в настоящей сборке, включая вариант с путями `..\` в `advanced\` — иначе парсер профилей не на чем проверять.

Заглушка `main.py` воспроизводит всё, на что смотрит супервизор: печатает в **stderr** строки старта с задержками, среди них строки с `\r` (иначе замену последней строки не проверить), поднимает `/system_stats` через заданное число секунд, уважает `--port` и `--disable-auto-launch`, отдаёт `/object_info` с выдуманными нодами и принимает `/userdata`.

Режимы задаются аргументами, каждый отвечает сценарию из `specs/`:

| Режим | Что проверяет |
|---|---|
| Старт за 2 секунды | Штатный путь |
| Долгий старт | Что ожидание готовности не обрывается раньше времени |
| Выход с ошибкой | Аварийное завершение, `US-RUN-06` |
| Зависание без ответа | Таймаут готовности |
| Самоперезапуск | Перезапуск сервера извне, `US-RUN-07` |
| Занятый порт | Выдача следующего свободного, `US-RUN-02/AC-7` |

**Чего стенд не заменяет:** отсутствия 403 у дочернего вебвью, перетаскивания картинок на холст, внешних ссылок, реального самоперезапуска от ComfyUI-Manager, настоящих категорий моделей. Это редкие проверки, а не ежедневные.

### Браузерный контур — отложен

Фронт можно поднимать отдельно и открывать в обычном браузере, но выгода меньше, чем кажется: горячая замена работает и в полном приложении. Реальных плюсов три — не нужен Rust-тулчейн, окно поднимается мгновенно, удобно ставить макет из `design/` рядом с живым экраном. Цена — слой заглушек для сгенерированных биндингов и набор фикстур. Решаем, когда появятся первые экраны.

## Выпуск

Артефакты живут в GitHub Releases, сайт документации ссылается на них кнопкой «Скачать». Репозиторий публичный — иначе ассеты не скачать без авторизации, а Pages требуют платного тарифа.

### Версия — единственный источник

`src-tauri/tauri.conf.json`, поле `version`. Тег обязан совпадать, и первым шагом воркфлоу это сверяется: `v<version>` против имени тега, расхождение роняет сборку. Без такой проверки однажды выйдет релиз, где тег говорит одно, а приложение показывает другое, и понять, что установлено у пользователя, станет невозможно.

### Воркфлоу `release-desktop.yml`

Триггер — пуш тега `v*`, раннер `windows-latest`.

Порядок: сверка тега с версией → Node и pnpm → Rust с кэшем Cargo → `pnpm install` → **ворота качества** → `tauri-apps/tauri-action`.

Ворота — это `node design/check.mjs`, `pnpm i18n:check` и проверка типов. Стоят до сборки намеренно: опубликованный инсталлятор с рассыпавшейся тёмной темой или недостающим переводом откатывать дороже, чем не выпускать.

`tauri-action` создаёт релиз **черновиком**. Следующий шаг считает SHA-256 и дописывает суммы в тело релиза, и только после этого черновик публикуется — так не бывает состояния, когда файл уже виден, а контрольной суммы ещё нет.

Тег с дефисом (`v0.2.0-beta.1`) помечается предрелизом. Тогда `releases/latest` его пропускает, и кнопка на сайте продолжает вести на стабильную версию.

Тело релиза берётся из секции `CHANGELOG.md` для этой версии.

### Состав релиза

| Файл | Зачем |
|---|---|
| `...-setup.exe` | Инсталлятор NSIS, установка в профиль пользователя |
| `...-setup.exe.sig` | Подпись обновления |
| `latest.json` | Манифест для апдейтера |
| `SHA256SUMS.txt` | Проверка целостности вручную |

Контрольные суммы здесь важнее обычного: приложение неподписанное, и сверка суммы — единственный доступный пользователю способ убедиться, что файл не подменили.

### Кнопка «Скачать» на сайте

Ссылка не пишется руками и не добывается запросом из браузера. VitePress выполняет загрузчики данных во время сборки: `download.data.ts` спрашивает у GitHub API последний непредрелизный выпуск и отдаёт версию, ссылку, размер, дату и контрольную сумму. Всё попадает в статику — на странице не остаётся ни одного сетевого запроса.

**Сборка сайта не должна падать из-за GitHub.** При недоступном API или исчерпанном лимите запросов загрузчик возвращает запасной вариант — ссылку на страницу релизов без подробностей. Сайт публикуется всегда.

**Сайт пересобирается по публикации релиза**: воркфлоу выпуска в конце дёргает деплой документации. Иначе кнопка отставала бы до следующей правки доков.

Рядом с кнопкой — версия, дата, размер, контрольная сумма и ссылка на все версии: пользователь должен видеть, что качает, до клика.

### Подписи нет, и это надо объяснить

Azure Trusted Signing — самый дешёвый путь — доступен только организациям и самозанятым из США и Канады. Обычный OV-сертификат стоит сотни долларов в год и всё равно требует накопления репутации, прежде чем SmartScreen успокоится. Решение: раздавать без подписи.

Отсюда обязательная страница `guide/smartscreen`: как выглядит предупреждение «Windows защитила ваш компьютер», почему оно появляется, что нажать, как сверить контрольную сумму, и прямое признание, что подписи нет. Ссылка на неё стоит рядом с кнопкой скачивания, а не прячется в глубине документации: без объяснения заметная часть людей решит, что скачала вирус.

### Автообновление

Три требования Tauri v2, каждое легко пропустить: `bundle.createUpdaterArtifacts: true`, пара ключей от `tauri signer generate` (публичный в `plugins.updater.pubkey`, приватный и пароль — в секреты CI), и поле `signature` в `latest.json`, которое содержит **содержимое** `.sig`, а не путь к нему.

**Приватный ключ хранится вне репозитория и резервируется.** При его утере выпустить обновление для уже установленных копий будет невозможно никогда.

**Подпись обновлений — не подпись кода.** Ключи minisign доказывают, что обновление выпустили вы; на SmartScreen они не влияют. Механизмы разные.

**Обновление никогда не ставится молча — и вот почему это критично.** На Windows приложение принудительно закрывается во время установки: таково ограничение инсталлятора. А дочерние процессы у нас живут в Job Object с `KILL_ON_JOB_CLOSE`. Складываем: пользователь генерирует картинку, соглашается на обновление — и ComfyUI умирает вместе с очередью, а следующий холодный старт займёт минуты.

Поэтому перед установкой приложение смотрит, есть ли работающие инстансы, и при наличии предлагает выбор: остановить их и обновиться либо отложить установку до следующего запуска.

**Проверка обновлений отключаема.** Она единственное, что приложение отправляет наружу, и это оговорено отдельным исключением в `NFR-350`.

```

  discovery/
    mod.rs            — trait InstanceDiscovery
    windows_portable.rs — валидация портабл-папки + парсинг .bat в профили
  supervise/
    mod.rs            — trait ProcessSupervisor
    windows.rs        — Job Object, CREATE_SUSPENDED, taskkill
  profiles.rs         — модель LaunchProfile, мутация аргументов перед стартом
  shared_models.rs    — скан общей папки, генерация YAML, применение к инстансу
  workflows.rs        — библиотека, манифест, добавление в инстанс, диф нод
  installer.rs        — разбор 7z, распаковка, клонирование дерева
  process.rs          — стейт-машина, кольцевой буфер логов, readiness-поллинг
  ports.rs            — выдача свободного порта
  webview.rs          — создание/показ/скрытие/ресайз child webview
  commands.rs         — tauri::command слой

```

Два трейта — единственные места, где живёт платформозависимость. Всё остальное платформо-нейтрально по построению. Обоснование — в разделе «Кроссплатформенность».

### discovery/windows_portable.rs

Папка считается валидным инстансом если существуют `python_embeded\python.exe` **и** `ComfyUI\main.py`. Дополнительно читаем `ComfyUI\comfyui_version.py` (переменная `__version__`) и выводим `python --version`. Сканируем `*.bat` в корне и в `advanced\`, исключая `update\`.

Реестр в `app_data_dir()/instances.json` через `tauri-plugin-store` (почему не хардкод пути — см. «Дисциплину хранения данных»):
```ts
{ id, name, description, path, accentColor, preferredPort,
  profiles: LaunchProfile[], lastProfileId, createdAt,
  source?: { archivePath, archiveLabel, installedAt } }
```
`source` заполняет мастер установки — по нему в карточке видно, из какого архива развёрнут инстанс. У добавленных вручную папок его нет.

### Парсинг .bat (сидирование профилей)

Построчно: игнорируем `@echo off`, `echo`, `pause`, `rem`/`::`. Строки `set KEY=VALUE` собираем в env-оверрайды. Ищем строку с `python.exe` (без учёта регистра), токенизируем с учётом кавычек. Первый токен — путь к интерпретатору, резолвим относительно директории `.bat` (плюс раскрытие `%~dp0`), остальное — аргументы.

Результат — редактируемый `LaunchProfile { id, name, pythonPath, args[], cwd, env }`. Пользователь может править аргументы в UI и сохранять свои профили поверх распарсенных. Если парсинг провалился — фолбэк на `cmd /c` с предупреждением в UI.

**Перед запуском мутируем args:** удаляем существующий `--port`, дописываем `--port <выданный>` и `--disable-auto-launch`.

### supervise/ + process.rs — самая рискованная часть

`trait ProcessSupervisor` — узкий контракт: `spawn(cmd) -> Handle`, `kill(handle)`, плюс гарантия «дети умирают вместе с родителем». Всё ниже — детали windows-реализации; вызывающий код о них не знает.

- **Job Object.** Один на приложение, создаётся при старте с `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`. Процессы спавним с `CREATE_SUSPENDED | CREATE_NO_WINDOW`, вызываем `AssignProcessToJobObject`, затем `ResumeThread`. Без этого падение нашего приложения оставит python-сирот, держащих VRAM.
- **Env:** `PYTHONUNBUFFERED=1` (иначе логи не появятся первые минуты — stdout блочно буферизуется при пайпе) и `PYTHONIOENCODING=utf-8`.
- **Логи.** ComfyUI пишет в **stderr**, не stdout. Читаем оба потока в отдельных тредах. Кольцевой буфер на ~5000 строк в памяти + эмит событий во фронт. tqdm использует `\r` — режем чанки и по `\n`, и по `\r`; если сегмент завершился `\r`, **заменяем** последнюю строку, а не добавляем новую, иначе прогрессбар превратится в десятки тысяч строк.
- **Readiness.** Опрос `GET http://127.0.0.1:<port>/system_stats` раз в 500 мс, таймаут 5 минут (холодный старт с кучей кастомных нод — это реально минуты). Параллельно ловим в логе `To see the GUI go to`.
- **Стейт-машина:** `Stopped → Starting → Running → Stopping → Stopped | Crashed`.
- **Остановка.** На Windows нельзя послать SIGINT чужому процессу. Используем `taskkill /PID <pid> /T /F`, затем ждём освобождения порта.

### ports.rs

Пробный `TcpListener::bind("127.0.0.1:0")` либо скан вверх от 8188. Порядок: берём `preferredPort` инстанса → если занят, выдаём следующий свободный и показываем это в UI.

### webview.rs — встраивание

```rust
WebviewBuilder::new(format!("comfy-{id}"), WebviewUrl::External(url))
    .disable_drag_drop_handler()        // критично, см. ниже
    .initialization_script(INJECT_JS)
    .on_navigation(|url| { /* чужой хост → opener::open_url, вернуть false */ })
```
Дочерний webview добавляется через `WebviewWindow::add_child(builder, position, size)`, по одному на запущенный инстанс.

- **Bounds.** Фронт сообщает прямоугольник области контента командой `set_webview_bounds(id, x, y, w, h)` — на маунте, на ресайзе окна, на сворачивании рейла. Ресинк вручную обязателен, автолейаута нет.
- **Контейнер этой области не может быть прокручиваемым.** Ни у одного его родителя не должно быть `overflow: auto`: прокрутка сместила бы нашу разметку, но не нативное окно, и они разъехались бы. Экран работающего инстанса — единственный, где прокрутки нет вовсе; на всех остальных прокручивается только область данных (`NFR-420`, `NFR-440`).
- **Переключение табов:** `show()` / `hide()` на дочерних вебвью.
- **`initialization_script` работает и на удалённых URL** (под капотом `AddScriptToExecuteOnDocumentCreated`) — можно прятать родное меню ComfyUI, перехватывать `window.open`, вешать свои хоткеи.
- **IPC из ComfyUI-страницы:** отдельный capability-файл, разрешающий origin `http://127.0.0.1:*` узкий список команд.

## Дисциплина хранения данных

Сквозное ограничение: пользователь ставит `.exe`, а при удалении через «Установка и удаление программ» с диска исчезает всё лишнее — но **не** модели и **не** библиотека воркфлоу. Это диктует, где и что мы пишем, поэтому правило вынесено отдельно от фич.

| Класс | Где | Что при удалении приложения |
|---|---|---|
| Состояние приложения — реестр инстансов, настройки, путь к библиотеке | `app_data_dir()` → `%APPDATA%\<identifier>` | Стирается чекбоксом инсталлятора |
| Производное — кэш `/object_info`, данные WebView2 | `app_local_data_dir()` → `%LOCALAPPDATA%\<identifier>` | Стирается тем же чекбоксом |
| Контент пользователя — модели, библиотека воркфлоу | Папки, выбранные пользователем | **Не трогаем никогда** |

### Что реально удаляет инсталлятор

Из шаблона NSIS-инсталлятора Tauri: при отмеченном чекбоксе «Delete application data» и **не** в режиме обновления (`$UpdateMode <> 1`) выполняется

```
RmDir /r "$APPDATA\${BUNDLEID}"
RmDir /r "$LOCALAPPDATA\${BUNDLEID}"
DeleteRegKey SHCTX "${MANUPRODUCTKEY}"   (+ ещё несколько ключей)
```

Три следствия, каждое — правило:

- **Удаляется путь строго по bundle identifier.** Поэтому никакого хардкода вида `%APPDATA%\comfyui-portable-organizer`: только `app_data_dir()` и `app_local_data_dir()`. Литерал разойдётся с `${BUNDLEID}`, и очистка пройдёт мимо.
- **Данные WebView2** (`$LOCALAPPDATA\<identifier>\EBWebView`) покрываются автоматически, отдельно чистить не нужно.
- **MSI такого чекбокса не имеет** и оставляет `%LOCALAPPDATA%\<id>` — это [tauri#6113](https://github.com/tauri-apps/tauri/issues/6113). Поэтому собираем **только NSIS `.exe`**, `installMode: currentUser` (без прав администратора, ставится в `%LOCALAPPDATA%\Programs`). MSI не собираем.

### Остальные правила

- **Bundle identifier фиксируется в Фазе 0 и не меняется никогда.** Смена идентификатора осиротит данные всех предыдущих установок — они останутся на диске навсегда.
- **Обновление — не удаление.** Установка новой версии поверх старой, хоть вручную, хоть апдейтером, идёт в режиме обновления: инсталлятор пропускает очистку данных, настройки и реестр инстансов сохраняются. Это то же поведение, что описано выше для `$UpdateMode`.
- **Кэш только в local.** `%APPDATA%` роумится в доменных профилях, снимкам `/object_info` там не место.
- **Куда не пишем ничего:** `Documents`, `%PROGRAMDATA%`, реестр помимо инсталлятора, папка рядом с exe.
- **Два исключения, оба по кнопке пользователя:** `extra_model_paths.yaml` в режиме «файл в инстансе» и копии воркфлоу в инстанс. Оба файла лежат в чужой установке и при удалении приложения не убираются — это осознанный выбор, но он должен быть написан в документации.
- **Экран «О приложении»** перечисляет: где лежат данные приложения (с кнопкой «открыть папку»), где лежит контент пользователя, что именно исчезнет при удалении. Пользователь не должен об этом догадываться.

## Общее хранилище моделей

Каждая портабл-установка держит собственную `ComfyUI\models\`. Один чекпоинт — 2-20 ГБ, при 3-5 инсталляциях выбор у пользователя только между дублированием сотен гигабайт и ручной вознёй с симлинками. В ComfyUI для этого есть штатный механизм — `extra_model_paths.yaml`, и наша задача сводится к тому, чтобы сгенерировать корректный файл и подсунуть его инстансу.

### Что выяснено из исходников (ComfyUI 0.30.2)

Разведка изменила дизайн относительно очевидного «просто писать файл в папку инстанса». Ключевые факты:

| Факт | Где | Следствие |
|---|---|---|
| Есть флаг `--extra-model-paths-config PATH [PATH ...]`, `nargs='+'`, `action='append'` | `comfy/cli_args.py:71` | Конфиг можно держать целиком у себя и **не писать в установку пользователя** |
| Сначала грузится `ComfyUI/extra_model_paths.yaml`, **потом** файлы из флага | `main.py:130-136` | Флаг не конфликтует с существующим файлом юзера, а дополняет его |
| `add_model_folder_path` делает `paths.append()`, при `is_default` — `paths.insert(0, …)` | `folder_paths.py:373-389` | Пути **аддитивны**: локальные модели не теряются. `is_default` управляет только тем, куда качать новое |
| Имя секции верхнего уровня произвольно, конфиг просто итерируется по ключам | `utils/extra_config.py:10` | Берём своё имя `cpo_shared_<n>` — не столкнёмся с чужой секцией `comfyui:` |
| `base_path` проходит `expandvars`/`expanduser`, относительный резолвится от папки YAML | `utils/extra_config.py:15-19` | Пишем абсолютные пути, неоднозначности нет |
| Значение ключа режется по `\n` | `utils/extra_config.py:24` | Многострочный `\|` — несколько путей на один ключ |
| `map_legacy`: `unet` → `diffusion_models`, `clip` → `text_encoders` | `folder_paths.py:111-114` | Подпапки `unet/` и `clip/` в общей папке отдаём под каноническими ключами |
| `custom_nodes` и `datasets` — валидные ключи этого YAML | `folder_paths.py:45,47` | `custom_nodes` жёстко в чёрный список, см. ниже |
| Список ключей формируется в рантайме и растёт от версии к версии | `folder_paths.py:24-70` | Хардкод списка в Rust протухнет — генерируем секции из реальных подпапок |
| `GET /models` — список ключей, `GET /internal/folder_paths` — `{ключ: [пути]}` | `server.py:342-346`, `server.py:1226` | Объективная проверка «конфиг подхватился» вместо разглядывания UI |

**Про `custom_nodes` отдельно.** Ключ валиден, и в поставляемом ComfyUI примере он присутствует — пользователь легко включит его, скопировав пример себе. Шаринг custom_nodes отменяет саму причину существования проекта: инстансы заведены ровно потому, что кастомные ноды конфликтуют между собой. Наш генератор исключает этот ключ безусловно и объясняет в UI почему.

### Модель данных

Глобальные настройки:
```ts
sharedModels: {
  roots: [{ id, path, label, enabled }],   // MVP: UI добавляет один, модель — массив
  makeDefaultTarget: boolean               // → is_default, по умолчанию true
}
```
На инстансе: `sharedModels: { enabled: boolean, applyMode: 'flag' | 'instanceFile' }`, по умолчанию `'flag'`.

Массив корней в MVP заполняется одним элементом, но формат заложен сразу: позже бесплатно ложится сценарий «быстрый SSD под checkpoints, HDD под архив» — YAML это умеет, одна секция на корень, а порядок корней определяет приоритет поиска.

### Генерация YAML — `shared_models.rs`

Три функции: `scan_root` (читает подпапки корня, маппит имена на канонические ключи с учётом `map_legacy`, возвращает распознанные и нераспознанные), `render_yaml`, `apply_to_instance`.

**Ключевое правило: секции строятся из реально существующих подпапок общего корня, а не из захардкоженного списка ключей.** Имена подпапок и есть ключи. Известная таблица ключей нужна только чтобы предложить создать недостающие стандартные папки и подсветить нераспознанное. Так конфиг не протухает с обновлением ComfyUI.

Прямые слэши — на Windows работают и не требуют экранирования:

```yaml
# Сгенерировано ComfyUI Portable Organizer. Ручные правки будут перезаписаны.
cpo_shared_0:
  base_path: D:/AI/_shared_models
  is_default: true
  checkpoints: checkpoints/
  loras: loras/
  vae: vae/
  text_encoders: |
    text_encoders/
    clip/
  diffusion_models: |
    unet/
    diffusion_models/
  controlnet: controlnet/
  upscale_models: upscale_models/
  embeddings: embeddings/
```

### Два режима применения

**Режим «флаг» — по умолчанию.** Файл живёт в `app_data_dir()/shared-models.yaml` и перегенерируется при изменении настроек. Перед стартом к аргументам дописывается `--extra-model-paths-config <абсолютный путь>` — **рядом с уже описанной мутацией `--port` и `--disable-auto-launch`**. Никакого нового механизма не появляется, только ещё один аргумент.

Плюсы: в установку пользователя не пишется ничего, выключение — снятие галки, один конфиг на все инстансы правится в одном месте.

**Режим «файл в инстансе».** Кнопка «Добавить общие модели» пишет `<instance>\ComfyUI\extra_model_paths.yaml`. Нужен тем, кто иногда стартует инстанс через `.bat` мимо нашего приложения. Политика коллизий:

- файла нет → пишем;
- файл есть и он наш (узнаём по маркерной строке в шапке) → перезаписываем молча;
- файл есть и он чужой → **молча не трогаем**. Показываем экран сравнения, бэкапим в `extra_model_paths.yaml.bak-<timestamp>` и пишем только после явного подтверждения. Альтернатива в том же экране — «оставить файл как есть, применить флагом».

Отключение в этом режиме — удаление нашего файла с восстановлением бэкапа, если он был.

### UI

Новый роут **«Настройки → Общие модели»** (роут, а не модалка — дисциплина z-order): выбор папки, сводка «распознано категорий N, с файлами M, суммарно X ГБ», тумблер «скачивать новые модели сюда» (`is_default`), список нераспознанных подпапок, предпросмотр сгенерированного YAML.

На экране инстанса — тумблер «Общие модели». Общий корень не настроен — ведёт на экран настройки; настроен — показывает режим применения и ссылку на его смену. В карточке подключённого инстанса значок.

## Библиотека воркфлоу

Воркфлоу живут внутри каждой установки и между инстансами не переносятся — «тот самый рабочий граф» приходится искать по папкам вручную. Заводим общую библиотеку избранных JSON и добавляем их в конкретные инстансы.

### Что выяснено из исходников

| Факт | Где |
|---|---|
| Библиотека инстанса — `user/default/workflows/*.json` | проверено на живой установке |
| `POST /userdata/{file}` — загрузка; `?overwrite=false` даёт **409** при конфликте, `?full_info=true` возвращает размер и mtime | `app/user_manager.py:364-400` |
| `GET /v2/userdata?path=workflows` — листинг с `name/type/path/size/modified` | `app/user_manager.py:214-240` |
| `DELETE /userdata/{file}`, `POST /userdata/{file}/move/{dest}` | `app/user_manager.py:427,437` |
| Путь URL-декодируется, есть защита от traversal через `commonpath` | `app/user_manager.py:88-96` |
| `GET /object_info` — все доступные классы нод | `server.py:800` |
| В JSON воркфлоу узлы лежат в `nodes[].type` | проверено на реальном файле |
| `--user-directory` может перенести весь `user/` в другое место | `comfy/cli_args.py:254` |

Последний пункт — ловушка: путь к папке воркфлоу **нельзя предполагать**, его надо резолвить из аргументов профиля.

### Хранилище

Настройка `workflowLibrary.path` — папка, выбранная пользователем. По умолчанию предлагаем соседнюю с корнем общих моделей (`<родитель>\workflows`), но жёсткой связи нет: библиотека работает и без настроенных общих моделей.

```
<library>/
  _library.json      манифест
  <подпапки по вкусу>/
  *.json
```

Манифест лежит **в самой библиотеке**, а не в данных приложения. Библиотека самодостаточна: переживает удаление и переустановку, переносится на другую машину целиком. В `app_data_dir()` хранится только путь к ней.

```ts
{ version: 1,
  items: {
    "sdxl/base.json": { favorite: true, tags: ["sdxl", "upscale"],
                        note: "…", addedAt, sourceInstanceId? }
  } }
```

**Правило устойчивости:** файл без записи в манифесте валиден и показывается как есть; запись без файла помечается «потерян» с предложением убрать. Библиотека — это папка с файлами, манифест лишь обогащает её. Ручная правка папки в проводнике ничего не ломает.

### Наполнение библиотеки

- Кнопка «Добавить файл» и drag&drop JSON на экран библиотеки. Конфликта с ComfyUI нет: у дочернего вебвью стоит `disable_drag_drop_handler()`, там дроп принадлежит канвасу, а наш живёт на нашем HTML.
- «Забрать из инстанса»: у запущенного — `GET /v2/userdata?path=workflows`, затем `GET /userdata/{file}`; у остановленного — чтение папки с диска.

### Добавление в инстанс

- **Запущен** → `POST /userdata/workflows%2F<name>.json?overwrite=false`. Ответ 409 → диалог «перезаписать / сохранить под другим именем».
- **Остановлен** → копия файла в `<user-dir>\default\workflows\`. **`<user-dir>` резолвим из аргументов профиля**, а не предполагаем: там может стоять `--user-directory`. Дефолт — `<instance>\ComfyUI\user`.
- Массовые операции в обе стороны: несколько воркфлоу в один инстанс и один воркфлоу в несколько инстансов.

### Проверка совместимости

То, ради чего фича живёт в нашем приложении, а не в проводнике. Из JSON собираем множество `nodes[].type`, у запущенного инстанса берём ключи `GET /object_info`, разницу показываем как «в этом инстансе нет нод: X, Y». Это предупреждение, а не блокировка.

Для остановленного инстанса точного ответа нет, поэтому при каждом успешном старте кэшируем снимок `/object_info` в `app_local_data_dir()` и сверяемся с ним, помечая ответ как «по данным последнего запуска». Кэш производный, его потеря безболезненна — отсюда и local.

### UI

Роут «Библиотека воркфлоу»: список с поиском по имени и тегам, фильтр «избранное», карточка с тегами и заметкой, кнопка «Добавить в инстанс» со списком инстансов и значком совместимости у каждого. На экране инстанса — вкладка «Воркфлоу»: что уже внутри и что можно забрать в библиотеку.

**Чего не делаем:** не редактируем графы, не рисуем превью канваса, не версионируем, не доустанавливаем недостающие ноды — последнее дело ComfyUI-Manager, мы только сообщаем.

**Отвергнутые варианты.** *Шарить весь `user/` через `--user-directory`* — одним флагом уносятся не только воркфлоу, но и настройки фронта и состояние расширений; у инстансов с разными наборами нод они конфликтуют, то есть ровно та беда, ради которой инстансы и разведены. *Junction на папку `workflows`* — правка одного воркфлоу молча меняет его во всех инстансах, а случайное удаление папки бьёт по всем сразу. Каталоговый junction на Windows прав администратора не требует, так что технически вариант открыт, но не как поведение по умолчанию.

## Мастер установки

Приложение закрывает не только организацию, но и установку: пользователь скачивает `.7z` сам, а мастер разворачивает его сразу в одну или несколько папок, регистрирует инстансы и подключает их к общим ресурсам. Мастер — постоянный раздел, а не разовый шаг первого запуска: он же используется, чтобы позже раскатать новую версию рядом со старыми.

### Что выяснено на реальном архиве

Мерил на `ComfyUI_windows_portable_nvidia.7z`, 2 110 797 220 байт.

| Факт | Следствие |
|---|---|
| Самый глубокий файл — 263 символа с внешней папкой, около **206 относительно корня архива** после среза `ComfyUI_windows_portable/` | При `MAX_PATH` 260 назначение длиннее ~54 символов ломает распаковку. Нужны verbatim-пути `\\?\` — `std::fs` сам их не добавляет, только `canonicalize()` |
| Рабочая установка занимает 52 ГБ при архиве 2.1 ГБ (с накопленными моделями) | Свободное место считаем из заголовка архива, а не из эмпирики |
| Обход дерева в 52 ГБ занял больше пяти минут | «Размер на диске» на экране инстанса — только асинхронно и с кэшем |
| В архиве одна корневая папка `ComfyUI_windows_portable/` | Срезаем её, имя папки задаёт пользователь. Заодно минус 25 символов к длине пути |
| [`sevenz-rust2`](https://github.com/hasenbanck/sevenz-rust2) — живой форк заброшенного `sevenz-rust`, чистый Rust, умеет LZMA2 и **BCJ2** | BCJ2 обязателен: 7-Zip применяет его к `.exe` и `.dll`, которых в `python_embeded` много, и декодер без него архив не откроет |

### Шаги

1. **Архив.** Путь к `.7z` из истории или новый. Перед использованием проверяем существование, размер и mtime — файл могли удалить или подменить. Хранится именно **история**, а не один путь: пользователь держит несколько версий.
2. **Разбор.** Заголовок даёт число записей, суммарный несжатый размер и корневую папку. Показываем до начала работы.
3. **Назначения.** Одно или несколько; на каждое путь, имя, описание, акцентный цвет. Валидация: папка пуста или не существует, места хватает, длина пути в безопасных пределах.
4. **Общие ресурсы.** Тумблеры подключения к общим моделям и библиотеке воркфлоу — теми же компонентами, что в «Настройках».
5. **Выполнение.** Распаковка в первую цель, копирование в остальные, регистрация в реестре.
6. **Итог.** Созданные инстансы, кнопка «Запустить».

### Модель данных

```ts
installer: {
  archives: [{ path, sizeBytes, mtime, label, lastUsedAt }],
  lastArchivePath
}
```
У инстанса — `description` и `source: { archivePath, archiveLabel, installedAt }`.

### installer.rs

`probe_archive` → `ArchiveInfo { entries, totalUncompressed, singleRoot }`, `extract` со срезом корня, `clone_tree` — обе операции со стримингом прогресса.

**Распаковываем один раз, дальше копируем.** Декомпрессия упирается в CPU и стоит дороже всего; копирование готового дерева упирается в диск. При двух-трёх целях экономит минуты.

**Атомарность обязательна.** Распаковываем во временную `<dest>.cpo-partial`, по завершении `rename`. Причина конкретная: валидация инстанса в `discovery` — это наличие `python_embeded\python.exe` и `ComfyUI\main.py`, и **полураспакованное дерево её пройдёт**. Без временной папки прерванная установка оставит битый инстанс, который приложение сочтёт рабочим. Отмена и падение убирают временную папку.

**Свободное место** проверяем до начала, из заголовка, с запасом, умножая на число целей на одном томе.

**Прогресс** детерминантный, на экране мастера: текущий файл, обработано и всего байт, отдельная фаза на каждую цель.

### Спайк на скорость

До того как фиксировать `sevenz-rust2`, замерить его на реальном 2.1 ГБ архиве против 7-Zip. LZMA2 в один поток может оказаться в разы медленнее. Если разрыв неприемлем — бандлим `7za.exe` с парсингом прогресса из вывода, ценой +1-2 МБ к инсталлятору и упоминания LGPL в лицензиях. Решение фиксируется в этом разделе по результату замера.

### Чего не делаем

Не скачиваем архив сами — источник выбирает пользователь. Не обновляем существующий инстанс на месте: мастер разворачивает новое рядом, старые версии остаются нетронутыми, что и требуется.

## Кроссплатформенность: швы сейчас, порт потом

Собираем **только под Windows**. Но два шва закладываем сразу, потому что стоят они пару часов, а без них будущий порт превращается в переписывание.

**Что перенеслось бы бесплатно:** весь фронтенд, оболочка Tauri, `initialization_script`, `on_navigation`, child webview API.

**Что требует второй реализации:**

| | Windows (делаем) | unix (не делаем) |
|---|---|---|
| Убийство сирот | Job Object + `KILL_ON_JOB_CLOSE` | Linux: `PR_SET_PDEATHSIG`. macOS: только process group + вотчдог, гарантия слабее |
| Остановка сервера | `taskkill /T /F`, только жёстко | `kill(-pgid, SIGINT)` — graceful, чего Windows не умеет |
| Скрытие консоли | `CREATE_NO_WINDOW` | не нужен |

**Настоящий блокер — предметная область, а не Tauri.** Портабл-сборки ComfyUI вне Windows не существует: нет `python_embeded`, нет `.bat`. Инстанс там — это `main.py` плюс venv/conda/uv где-то рядом, а профили запуска не из чего парсить. Поэтому `InstanceDiscovery` абстрагирует ровно две операции: «валидна ли эта папка» и «какими профилями её засеять». Windows-реализация читает `python_embeded` и `.bat`; гипотетическая unix-реализация искала бы `venv/bin/python` и отдавала бы захардкоженные пресеты аргументов.

Ключ к этому — **`LaunchProfile` первичен, а парсинг `.bat` лишь один из способов его заполнить.** Профиль в любом случае редактируемый, так что unix-версия просто не имела бы шага сидирования.

**Известный риск, если порт когда-нибудь случится:** на Linux Tauri даёт WebKitGTK вместо Chromium, а у него проблемы с производительностью canvas и WebGL. Канвас ComfyUI с сотней нод может там ощутимо тормозить, и со стороны приложения это не чинится. macOS в этом смысле безопасен — WKWebView это по сути Safari, ComfyUI в нём работает. То есть если приоритетом когда-то станет именно Linux, честный ответ — переезд на Electron с `WebContentsView`, а не борьба с WebKitGTK.

**Чего явно НЕ делаем сейчас:** unix-реализаций трейтов, CI под мак/линукс, кросс-платформенных путей в конфиге, абстракций поверх разделителя пути. `PathBuf` и так справляется.

## Дисциплина z-order (влияет на дизайн UI)

Child webview — нативное окно **поверх** нашего HTML. Дропдауны и модалки нашего интерфейса физически не могут перекрыть область ComfyUI. Правила:

1. Вся оболочка (рейл навигации, тулбар) живёт в зарезервированном месте лейаута и никогда не налезает на контент — см. следующий раздел.
2. Настройки, добавление инстанса, редактор аргументов — **отдельные роуты**, а не модалки поверх.
3. Если глобальный диалог неизбежен (подтверждение выхода) — сначала `hide()` активного child webview, потом показ диалога.
4. Выпадашка выбора профиля запуска рендерится на экране инстанса **до** старта, когда webview ещё не создан. Проблемы нет.

## Навигация и структура приложения

Рейл выводится из ограничения z-order выше, а тосты и экраны ниже опираются уже на готовую структуру — отсюда место раздела.

### Рейл

Слева, виден **всегда**, включая экран работающего инстанса. Иконки с подписями по умолчанию, кнопкой сворачивается до одних иконок, состояние запоминается. Подписи не косметика: в русском и испанском иконка без текста читается заметно хуже.

Два блока, разделённых чертой:

| Блок | Содержимое |
|---|---|
| Разделы | Инстансы · Установка · Библиотека воркфлоу · Настройки · О приложении |
| Запущенные | По иконке на каждый работающий инстанс, в его акцентном цвете, со статусом |

**Второй блок решает две задачи разом.** Переключение между работающими инстансами — один клик вместо трёх. И фоновые события снова видны всегда: упавший процесс или самоперезапуск от ComfyUI-Manager меняют статус прямо в рейле, а не прячутся внутри раздела «Инстансы». Именно сюда идут уведомления, не привязанные к действию пользователя (см. раздел про уведомления).

### Контентная область и вебвью

Контентный прямоугольник — окно минус рейл. Сворачивание рейла меняет его, значит требует ресинка `set_webview_bounds` тем же механизмом, что ресайз окна.

**Правило при навигации:** уход с работающего инстанса в любой другой раздел — `hide()` дочернего вебвью, возврат — `show()` плюс ресинк bounds. Процесс продолжает работать; останавливает его только явная команда.

### Разделы

1. **Инстансы** — список карточек со статусом; при пустом реестре приглашение перейти в «Установку». Клик по инстансу разворачивает его экран в контентной области.
2. **Установка** — две дорожки на одном экране: «Указать существующую папку» и «Мастер установки». Раздел постоянный, а не только для первого запуска.
3. **Библиотека воркфлоу**.
4. **Настройки** — внешний вид, общие модели, библиотека воркфлоу, архивы установщика, поведение.
5. **О приложении** — версия, пути данных с кнопками «открыть папку», что исчезнет при удалении.

**Канонический дом настроек общих ресурсов — раздел «Настройки».** Мастер установки встраивает те же компоненты отдельным шагом, чтобы первый запуск был цельным и пользователя не выкидывало в настройки на середине. Один компонент, два места показа — логика не дублируется.

Отдельного Welcome-экрана нет: его роль берут пустые состояния разделов «Инстансы» и «Установка».

## Интерфейс: тема, язык, уведомления

Порядок разделов неслучаен: тосты выводятся из ограничения z-order выше, а экраны ниже опираются на готовый каркас.

### Тема

Три состояния: `light`, `dark`, `system`. Выбор хранится в `app_data_dir()`.

Реализация на CSS custom properties, без препроцессоров и утилитарных классов:

- полная **светлая** палитра объявлена на голом `:root` — база, от которой ничего не отвалится;
- `@media (prefers-color-scheme: dark)` под гардом `:root:not([data-theme="light"])` — системный режим;
- `:root[data-theme="dark"]` — явный выбор, побеждает медиа-запрос в обе стороны.

Ни один цвет не должен иметь единственное определение внутри медиа-блока или `[data-theme]` — иначе в одном из трёх состояний он окажется неопределён.

- **Смена системной темы на лету** ловится через `matchMedia('(prefers-color-scheme: dark)')` внутри вебвью и применяется без перезапуска.
- **Титлбар.** Декорации системные, но шапку красим под нашу тему через `window.set_theme()` — иначе тёмное окно получит белый заголовок. **Меню-бара нет:** Tauri v2 на Windows его не создаёт, убирать нечего. Всё, что жило бы в меню, уже есть в оболочке — настройки и «О приложении» это роуты, выход это крестик. Меню остаётся только у трея.
- **Акцентный цвет инстанса** из реестра подмешивается как `--instance-accent` на корень экрана и обязан оставаться читаемым в обеих темах — проверка контраста при выборе цвета.

### Язык

`vue-i18n` v11, Composition API (`legacy: false`), по одному JSON на локаль: `en` (источник правды), `ru`, `zh-Hans`, `es`.

Правила, которые делают переводы дешёвыми:

- **Ключи семантические, а не английский текст:** `instance.start.button`, а не `"Start instance"`. Иначе правка формулировки на английском ломает все остальные локали.
- **`en.json` — единственный источник правды.** Новый ключ появляется сначала там.
- **Паритет ключей проверяется в CI.** Скрипт `pnpm i18n:check` сравнивает каждую локаль с `en.json` и падает и на недостающих, и на лишних ключах. Это самая ценная часть затеи: без неё локали расходятся молча.
- **Типизация ключей от `en.json`** через схему `vue-i18n` — неизвестный ключ становится ошибкой компиляции, а не пустой строкой в интерфейсе.
- **Русская плюрализация требует своего правила.** Три формы (1 инстанс / 2 инстанса / 5 инстансов), дефолтная логика `vue-i18n` их не даёт — регистрируем кастомный `pluralRules` для `ru`. Китайскому хватает одной формы, испанскому — стандартных двух.
- **Числа и даты только через `n()` и `d()`** с `numberFormats`/`datetimeFormats` на локаль. Размеры на диске тоже, иначе разделитель окажется чужим.
- **Определение языка при первом запуске:** `tauri-plugin-os::locale()` → `navigator.language` → `en`. Выбор пользователя перекрывает определение и живёт в настройках.
- **Переключение без перезагрузки** — `locale` реактивен; заодно обновляем атрибут `<html lang>`.
- **Шрифтовый стек обязан покрывать CJK:** `system-ui, "Segoe UI", "Microsoft YaHei", sans-serif`. Без этого китайский рендерится случайным фолбэком.
- **RTL не поддерживаем** — среди четырёх языков его нет. Записано явно, чтобы никто не строил лишнюю машинерию.

**Ошибки из Rust не переводятся на бэкенде.** Команды возвращают `AppError { code, params }`, фронт мапит `errors.<code>` в текст. Иначе переводы размажутся по двум языкам и двум слоям. Неизвестный код показывается как сам код — интерфейс не должен падать или показывать пустоту из-за пропущенного ключа.

**ComfyUI внутри вкладки не трогаем.** У него свои `Comfy.ColorPalette` и `Comfy.Locale` в `user/default/comfy.settings.json`, доступные через `GET/POST /settings/{id}` (`app/app_settings.py:37-57`). Синхронизация технически дешёвая, но это чужие настройки пользователя, и молча переписывать их мы не будем. Расхождение темы нашей оболочки и темы канваса — принятое решение, а не дефект.

### Уведомления

**Инвариант, снимающий конфликт с z-order:** любая операция, способная выдать тост, инициируется с экрана оболочки — добавление и удаление инстанса, настройка общих моделей, работа с библиотекой воркфлоу, смена настроек. На экране работающего инстанса пользователь работает внутри ComfyUI, и тостам там нечего показывать. Поэтому обычные плавающие тосты в углу области контента конфликта не создают: в момент их появления дочернего вебвью на экране нет.

- **Успех** — автоскрытие примерно через 4 секунды.
- **Ошибка** — висит до закрытия, разворачивается в детали, даёт копирование текста вместе с кодом ошибки.
- Очередь с лимитом одновременно видимых и схлопыванием повторов.

**События, не привязанные к действию пользователя** — падение процесса, самоперезапуск от ComfyUI-Manager — приходят, когда вебвью может быть на экране. Они идут не в тост, а в **блок запущенных инстансов в рейле** (статус плюс бейдж) и в консоль логов этого инстанса. Рейл — часть оболочки, он виден всегда.

### Прогресс

Глобальной полосы-лоадера **не будет**: почти все операции мгновенные, и постоянный индикатор на каждый чих только шумит. Прогресс живёт внутри экрана, которому операция принадлежит.

| Операция | Индикатор |
|---|---|
| Старт инстанса (до 5 минут) | Уже есть свой экран с живой консолью |
| Скан общей папки моделей, подсчёт размера | Индетерминантный, на экране «Общие модели» |
| Анализатор дубликатов (Фаза 4) | Детерминантный, на своём экране |
| Массовое добавление воркфлоу | Детерминантный счётчик N/M на экране библиотеки |

Правило: индетерминантный индикатор только там, где длительность заранее неизвестна; всё, что считается по шагам, показывает шаги.

## Грабли, которые надо обработать явно

- **Drag & drop.** Tauri по умолчанию перехватывает системный дроп файлов, что **сломает** перетаскивание картинок и workflow-json на канвас ComfyUI. Обязателен `disable_drag_drop_handler()` на дочернем webview.
- **Одновременный запуск двух инстансов = OOM по VRAM.** При старте второго — диалог «Instance X уже работает» с выбором: остановить тот / запустить всё равно.
- **ComfyUI-Manager перезапускает сервер сам** после установки нод — респавнит процесс, и наш хэндл его теряет. MVP: детектим выход процесса, ещё ~15 секунд опрашиваем порт; если `/system_stats` отвечает — показываем «сервер перезапустился вне нашего контроля» и предлагаем переподключиться. Полное решение (найти PID владельца порта через `GetExtendedTcpTable`) — после MVP.
- **Внешние ссылки и OAuth.** Ссылки на доки и вход в API-ноды должны уходить в системный браузер через `on_navigation`, иначе откроется голое окно WebView2 без всякой навигации.
- **Закрытие приложения при работающих серверах** → диалог: остановить всё / свернуть в трей. Нужен `tray-icon` + `single-instance`.
- **Пути с пробелами и кириллицей** — корректное квотирование при спавне, тесты на `d:\program files\...`.
- **Скачивания.** WebView2 показывает свой UI загрузок; «Сохранить изображение» из контекстного меню и экспорт workflow нужно проверить отдельно.
- **Подпись кода.** Неподписанный инсталлятор ловит SmartScreen. Решить до раздачи бинарников.
- **Конфиг общих моделей читается только при старте.** Смена настроек на работающем инстансе не даёт ничего до рестарта — UI обязан это писать явно, иначе пользователь решит, что функция сломана.
- **Общая папка на съёмном или сетевом диске.** Если недоступна при старте, ComfyUI не упадёт — просто не найдёт модели, и воркфлоу сломаются с «model not found» уже в процессе работы. Проверяем существование корня перед стартом, при отсутствии — предупреждение с выбором «запустить без общих моделей».
- **`is_default: true` меняет, куда ComfyUI-Manager качает модели** — в общую папку. Обычно это и нужно, но поведение должно быть проговорено в UI, а не всплыть сюрпризом.
- **Одинаковые имена файлов в локальной и общей папке.** Оба попадут в список ноды, победитель определяется порядком путей, то есть `is_default`. Такие коллизии показывать в анализаторе дубликатов.
- **`custom_nodes` не шарим никогда** — это отменило бы смысл раздельных инстансов.
- **Имя файла — идентификатор воркфлоу в ComfyUI.** Совпадение имён при добавлении даёт 409 либо тихую перезапись. Спрашиваем всегда.
- **Запущенный инстанс не перечитывает список воркфлоу сам** — новый появится после рефреша в UI ComfyUI. Сказать об этом в интерфейсе, иначе выглядит как «не сработало».
- **Папка библиотеки может быть недоступна** (сетевой или съёмный диск, папку удалили) — экран библиотеки обязан это пережить, а не упасть.
- **Bundle identifier менять нельзя** — иначе данные прошлых установок останутся на диске навсегда, см. «Дисциплину хранения данных».
- **Ретрофит i18n дороже, чем кажется.** Ни одной строки в шаблонах мимо `t()`, начиная с самого первого экрана.
- **Длина строк.** Испанский и русский заметно длиннее английского, китайский короче. Кнопки, рейл и таблицы проверять на самой длинной локали, а не на английской.
- **Плюрализация в русском** — три формы, дефолтные правила `vue-i18n` не подходят.
- **Цвет титлбара за темой сам не следует:** без `set_theme()` тёмное окно получит белую шапку.
- **Акцентный цвет инстанса** может оказаться нечитаемым в одной из тем — проверять контраст при выборе.
- **Тема ComfyUI внутри вкладки живёт отдельно** от нашей и может не совпадать. Это решение, а не дефект.
- **Лимит 260 символов при распаковке.** Самый глубокий файл архива — около 206 символов относительно корня. Назначение длиннее ~54 символов ломает установку без verbatim-путей `\\?\`.
- **Полураспакованное дерево проходит валидацию инстанса** — отсюда обязательная временная папка и `rename` в конце.
- **Антивирус.** Defender сканирует десятки тысяч новых файлов, распаковка идёт заметно дольше ожидаемого. Не чиним, но пишем в документации.
- **Размер на диске считается минутами** (52 ГБ обходились больше пяти минут) — только асинхронно и с кэшем, иначе экран инстанса зависнет.
- **Архив мог исчезнуть или измениться** между сессиями — проверять при каждом входе в мастер.
- **Сворачивание рейла меняет bounds вебвью** — забыть ресинк значит получить обрезанный или наехавший канвас.

### Результат спайка

Прогон автоматизирован: переменная `CPO_SPIKE=1` включает автозапуск всей последовательности, а ключевые факты печатаются в терминал с префиксом `[СПАЙК]`. Сделано так потому, что проверка кликом по кнопке невоспроизводима, а решение фазы должно опираться на лог, а не на впечатление.

Отдельного приёма потребовала главная проверка. Наш IPC в чужом origin недоступен, поэтому узнать, что именно увидела вкладка, напрямую нельзя. Обратный канал сделан через `document.title`: `on_page_load` выполняет в странице скрипт, кладущий в заголовок начало текста документа, а `on_document_title_changed` возвращает это в Rust. Если бы origin-middleware отбила запрос, в логе стояло бы `403`; вместо этого пришёл `ComfyUI`.

**Измеренное окружение:** Rust 1.97.1, MSVC Build Tools 17.14, WebView2 Runtime 151, Node 24.4, pnpm 11.21.

**Найдено по ходу и исправлено в этом документе:** `installMode` у NSIS называется `currentUser`, а не `perUser`; метод отключения перехвата дропа — `disable_drag_drop_handler()`, а не `drag_drop_handler_enabled(false)`.

### Генерация типов: работает, версии зафиксированы

`tauri-specta 2.0.0-rc.25` со `specta 2.0.0-rc.25`. Версии указаны точно и не случайно: `cargo add` без версии тянет стабильную ветку 1.x, а она под Tauri v1 и с нашим кодом несовместима.

Команды и события описываются один раз на Rust, `src/bindings.ts` генерируется, фронт вызывает только его. Doc-комментарии из Rust переезжают в TypeScript, так что подсказка в редакторе объясняет и назначение команды, и её ограничения.

**Одна ловушка, которую стоит запомнить:** имя события выводится из имени структуры. Событие `LogLine` уезжает на фронт под именем `log-line`, а не под тем, что было в ручном `emit`. Поэтому смешивать сгенерированные события с рукописными подписками нельзя — только через `events.*` из биндингов.

**Specta заставила исправить настоящий дефект.** Экспорт упал на `u64` в сигнатуре команды: такое число не помещается в JavaScript-число без потери точности, и библиотека отказывается это молча пропускать. Типы сужены до `u32` — секундам 64 бита не нужны. Руками написанные типы этот дефект пропустили бы, и он всплыл бы на больших значениях. Это ровно тот класс ошибок, ради которого генерация и заводилась.

**Известное ограничение:** сгенерировать типы тестом на Windows не выходит — тестовый бинарь падает с `0xC0000139` из-за `cdylib` в типах крейта. Поэтому экспорт происходит при запуске дев-сборки.
