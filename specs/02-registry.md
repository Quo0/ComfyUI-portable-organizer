# EP-REG — Реестр инстансов

Приложение знает об инстансах, но ими не владеет. Регистрация запоминает путь и метаданные; папка на диске остаётся нетронутой. Это главное обещание раздела и главный страх актора A2.

## Функциональные требования

| ID | Требование | Обоснование в `PLAN.md` |
|---|---|---|
| `FR-REG-010` | Приложение проверяет, что выбранная папка — портабл-сборка ComfyUI, и при отказе называет причину | «discovery/windows_portable.rs» |
| `FR-REG-020` | Регистрация не изменяет содержимое папки инстанса | «Дисциплина хранения данных» |
| `FR-REG-030` | Приложение определяет версию ComfyUI, версию Python и доступные профили запуска | «discovery/windows_portable.rs» |
| `FR-REG-040` | Инстансу задаются имя, описание, акцентный цвет и предпочитаемый порт | «discovery/windows_portable.rs» |
| `FR-REG-050` | Метаданные инстанса можно изменить после регистрации | «Экраны» |
| `FR-REG-060` | Удаление из реестра не удаляет папку с диска | «Чеклист, Фаза 1» |
| `FR-REG-070` | Для инстансов, развёрнутых мастером, сохраняется и показывается архив-источник | «Мастер установки» |
| `FR-REG-080` | Размер инстанса на диске вычисляется не блокируя интерфейс | «Грабли» |
| `FR-REG-090` | Повторная регистрация той же папки не создаёт дубликат | «discovery/windows_portable.rs» |

### US-REG-01 — Регистрация существующей папки

**Как** A2, владелец рабочей сборки
**я хочу** указать приложению свою папку ComfyUI
**чтобы** управлять ею отсюда, ничего в ней не сломав.

Теги: `@FR-REG-010` `@FR-REG-020` `@FR-REG-030` `@phase-1` `@area-reg`
Обоснование: `PLAN.md` → «discovery/windows_portable.rs»

**Предусловия**
- На диске есть распакованная портабл-сборка ComfyUI.

**Критерии приёмки**
- **AC-1.** Пользователь выбирает папку через системный диалог выбора папки.
- **AC-2.** Папка принимается, если содержит встроенный интерпретатор Python и главный файл ComfyUI.
- **AC-3.** Для принятой папки показаны: версия ComfyUI, версия Python и список найденных профилей запуска.
- **AC-4.** В список профилей попадают как основные варианты запуска, так и варианты из вложенной папки дополнительных сценариев.
- **AC-5.** Профили, относящиеся к обновлению сборки, в список не попадают — они не запускают сервер.
- **AC-6.** Пользователь видит распознанные профили до подтверждения регистрации.
- **AC-7.** После регистрации содержимое папки не изменилось: сборка по-прежнему запускается своими средствами мимо приложения.

**Негативные и краевые случаи**
- **AC-8.** Папка без встроенного интерпретатора или без главного файла ComfyUI отклоняется, и сообщение называет, чего именно не хватает.
- **AC-9.** При выборе папки на уровень выше или ниже нужной сообщение подсказывает, какую папку выбрать.
- **AC-10.** Если профили распознать не удалось, инстанс всё равно регистрируется, а пользователь предупреждён, что профили нужно задать вручную.
- **AC-11.** Повторный выбор уже зарегистрированной папки не создаёт второй инстанс, а показывает существующий.
- **AC-12.** Путь, содержащий пробелы и кириллицу, обрабатывается наравне с любым другим.

### US-REG-02 — Метаданные инстанса при регистрации

**Как** владелец нескольких сборок
**я хочу** дать инстансу понятное имя, описание и цвет
**чтобы** различать их с одного взгляда.

Теги: `@FR-REG-040` `@phase-1` `@area-reg`
Обоснование: `PLAN.md` → «discovery/windows_portable.rs»

**Предусловия**
- Папка прошла проверку и готова к регистрации.

**Критерии приёмки**
- **AC-1.** Пользователь задаёт имя инстанса; предложено осмысленное значение по умолчанию.
- **AC-2.** Пользователь может задать описание — свободный текст о назначении сборки.
- **AC-3.** Пользователь выбирает акцентный цвет, которым инстанс будет отличаться в списках.
- **AC-4.** Пользователь может задать предпочитаемый порт; предложено значение по умолчанию.
- **AC-5.** Выбранный акцентный цвет остаётся различимым и в светлой, и в тёмной теме.

**Негативные и краевые случаи**
- **AC-6.** Пустое имя не принимается.
- **AC-7.** Совпадение имени с уже существующим допускается, но пользователь предупреждён.
- **AC-8.** Значение порта вне допустимого диапазона не принимается с объяснением диапазона.

### US-REG-03 — Просмотр списка инстансов

**Как** владелец нескольких сборок
**я хочу** видеть все инстансы и их состояние
**чтобы** выбрать нужный.

Теги: `@FR-REG-030` `@FR-REG-070` `@FR-REG-080` `@phase-1` `@area-reg`
Обоснование: `PLAN.md` → «Экраны»

**Предусловия**
- В реестре есть хотя бы один инстанс.

**Критерии приёмки**
- **AC-1.** Для каждого инстанса видны имя, описание, акцентный цвет и текущее состояние.
- **AC-2.** Состояние различает как минимум: остановлен, стартует, работает, аварийно завершён.
- **AC-3.** Открытие инстанса показывает путь, версию ComfyUI, версию Python и размер на диске.
- **AC-4.** Для инстансов, развёрнутых мастером, показан архив-источник и дата установки.
- **AC-5.** Размер на диске появляется по мере вычисления и не задерживает показ остальных сведений.
- **AC-6.** Ранее вычисленный размер показывается сразу, с пометкой о том, когда он измерен.

**Негативные и краевые случаи**
- **AC-7.** Если папка инстанса исчезла с диска, инстанс помечается недоступным, а не пропадает из списка.
- **AC-8.** Недоступный инстанс нельзя запустить, и предложено либо указать новый путь, либо убрать его из реестра.
- **AC-9.** При пустом реестре список объясняет, как добавить первый инстанс.

### US-REG-04 — Изменение метаданных

**Как** владелец инстанса
**я хочу** переименовать его и поменять цвет
**чтобы** реестр отражал текущее назначение сборки.

Теги: `@FR-REG-050` `@phase-1` `@area-reg`
Обоснование: `PLAN.md` → «Чеклист, Фаза 1»

**Предусловия**
- Инстанс зарегистрирован.

**Критерии приёмки**
- **AC-1.** Имя, описание, акцентный цвет и предпочитаемый порт доступны для изменения.
- **AC-2.** Изменения сохраняются и переживают перезапуск приложения.
- **AC-3.** Изменение метаданных не затрагивает содержимое папки инстанса.
- **AC-4.** Изменение предпочитаемого порта у работающего инстанса не влияет на текущий запуск и применяется со следующего.

**Негативные и краевые случаи**
- **AC-5.** Ограничения на имя и порт те же, что при регистрации.

### US-REG-05 — Удаление из реестра

**Как** владелец инстанса, который больше не нужен
**я хочу** убрать его из приложения
**чтобы** список не захламлялся.

Теги: `@FR-REG-060` `@phase-1` `@area-reg`
Обоснование: `PLAN.md` → «Чеклист, Фаза 1»

**Предусловия**
- Инстанс зарегистрирован.

**Критерии приёмки**
- **AC-1.** Пользователь может убрать инстанс из реестра.
- **AC-2.** Перед удалением явно сказано, что папка на диске останется нетронутой.
- **AC-3.** Удаление требует подтверждения.
- **AC-4.** После удаления папку можно зарегистрировать заново, и она снова пройдёт проверку.
- **AC-5.** Файлы, ранее записанные приложением внутрь папки инстанса, при удалении из реестра не убираются; пользователю сказано, какие это файлы.

**Негативные и краевые случаи**
- **AC-6.** Работающий инстанс нельзя убрать из реестра, пока он не остановлен; предложено остановить.
