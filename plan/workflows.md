# Библиотека воркфлоу

> Раздел плана. Оглавление — [PLAN.md](../PLAN.md).

Воркфлоу живут внутри каждой установки и между инстансами не переносятся — «тот самый рабочий граф» приходится искать по папкам вручную. Заводим общую библиотеку избранных JSON и добавляем их в конкретные инстансы.

## Что выяснено из исходников

| Факт | Где |
|---|---|
| Библиотека инстанса — `user/default/workflows/*.json` | проверено на живой установке |
| `POST /userdata/{file}` — загрузка; `?overwrite=false` даёт **409** при конфликте, `?full_info=true` возвращает размер и mtime | `app/user_manager.py:364-400` |
| `GET /v2/userdata?path=workflows` — листинг с `name/type/path/size/modified` | `app/user_manager.py:214-240` |
| `DELETE /userdata/{file}`, `POST /userdata/{file}/move/{dest}` | `app/user_manager.py:427,437` |
| Путь URL-декодируется, есть защита от traversal через `commonpath` | `app/user_manager.py:88-96` |
| `GET /object_info` — все доступные классы нод | `server.py:800` |
| В JSON воркфлоу узлы лежат в `nodes[].type` | проверено на реальном файле |
| `--user-directory` может перенести весь `user/` в другое место | `comfy/cli_args.py:254` |

Последний пункт — ловушка: путь к папке воркфлоу **нельзя предполагать**, его надо резолвить из аргументов профиля.

## Хранилище

Настройка `workflowLibrary.path` — папка, выбранная пользователем. По умолчанию предлагаем соседнюю с корнем общих моделей (`<родитель>\workflows`), но жёсткой связи нет: библиотека работает и без настроенных общих моделей.

```
<library>/
  _library.json      манифест
  <подпапки по вкусу>/
  *.json
```

Манифест лежит **в самой библиотеке**, а не в данных приложения. Библиотека самодостаточна: переживает удаление и переустановку, переносится на другую машину целиком. В `app_data_dir()` хранится только путь к ней.

```ts
{ version: 1,
  items: {
    "sdxl/base.json": { favorite: true, tags: ["sdxl", "upscale"],
                        note: "…", addedAt, sourceInstanceId? }
  } }
```

**Правило устойчивости:** файл без записи в манифесте валиден и показывается как есть; запись без файла помечается «потерян» с предложением убрать. Библиотека — это папка с файлами, манифест лишь обогащает её. Ручная правка папки в проводнике ничего не ломает.

## Наполнение библиотеки

- Кнопка «Добавить файл» и drag&drop JSON на экран библиотеки. Конфликта с ComfyUI нет: у дочернего вебвью стоит `disable_drag_drop_handler()`, там дроп принадлежит канвасу, а наш живёт на нашем HTML.
- «Забрать из инстанса»: у запущенного — `GET /v2/userdata?path=workflows`, затем `GET /userdata/{file}`; у остановленного — чтение папки с диска.

## Добавление в инстанс

- **Запущен** → `POST /userdata/workflows%2F<name>.json?overwrite=false`. Ответ 409 → диалог «перезаписать / сохранить под другим именем».
- **Остановлен** → копия файла в `<user-dir>\default\workflows\`. **`<user-dir>` резолвим из аргументов профиля**, а не предполагаем: там может стоять `--user-directory`. Дефолт — `<instance>\ComfyUI\user`.
- Массовые операции в обе стороны: несколько воркфлоу в один инстанс и один воркфлоу в несколько инстансов.

## Проверка совместимости

То, ради чего фича живёт в нашем приложении, а не в проводнике. Из JSON собираем множество `nodes[].type`, у запущенного инстанса берём ключи `GET /object_info`, разницу показываем как «в этом инстансе нет нод: X, Y». Это предупреждение, а не блокировка.

Для остановленного инстанса точного ответа нет, поэтому при каждом успешном старте кэшируем снимок `/object_info` в `app_local_data_dir()` и сверяемся с ним, помечая ответ как «по данным последнего запуска». Кэш производный, его потеря безболезненна — отсюда и local.

## UI

Роут «Библиотека воркфлоу»: список с поиском по имени и тегам, фильтр «избранное», карточка с тегами и заметкой, кнопка «Добавить в инстанс» со списком инстансов и значком совместимости у каждого. На экране инстанса — вкладка «Воркфлоу»: что уже внутри и что можно забрать в библиотеку.

**Чего не делаем:** не редактируем графы, не рисуем превью канваса, не версионируем, не доустанавливаем недостающие ноды — последнее дело ComfyUI-Manager, мы только сообщаем.

**Отвергнутые варианты.** *Шарить весь `user/` через `--user-directory`* — одним флагом уносятся не только воркфлоу, но и настройки фронта и состояние расширений; у инстансов с разными наборами нод они конфликтуют, то есть ровно та беда, ради которой инстансы и разведены. *Junction на папку `workflows`* — правка одного воркфлоу молча меняет его во всех инстансах, а случайное удаление папки бьёт по всем сразу. Каталоговый junction на Windows прав администратора не требует, так что технически вариант открыт, но не как поведение по умолчанию.
