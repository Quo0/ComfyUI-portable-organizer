# Разработка

> Раздел плана. Оглавление — [PLAN.md](../PLAN.md).

Работа с Tauri здесь **полностью стандартная** — ни одного обходного пути. Но у приложения есть две особенности, о которые дев-цикл спотыкается, и знать о них лучше заранее.

## Что происходит по `pnpm dev:desktop`

Сначала `beforeDevCommand` поднимает Vite на `devUrl` (`localhost:1420`), затем собирается отладочный бинарь и открывается нативное окно, которое грузит этот самый localhost. Дев-сервер такой же, как у любого Vite-приложения, просто смотрит в него не браузер, а WebView2.

| Что правим | Что происходит | Сколько ждать |
|---|---|---|
| Vue, CSS, локали | Горячая замена, как в браузере | Мгновенно |
| Rust в `src-tauri/` | CLI следит за папкой, пересобирает и перезапускает окно | Секунды на инкрементальной сборке |

Первая сборка — минуты: Cargo компилирует Tauri со всеми зависимостями. Дальше быстро. Слежку выключает `--no-watch`, когда перезапуски мешают.

**Ничего в систему не ставится.** Отладочный бинарь лежит в `src-tauri/target/debug/` и запускается оттуда; инсталлятор появляется только у `tauri build`. Ставить и удалять программу на каждой правке не нужно.

**Devtools** — правым кликом «Inspect» либо `Ctrl + Shift + I`, в отладочной сборке включены.

**pnpm не требование Tauri.** Tauri знает только `beforeDevCommand` и `devUrl`, чем ставятся зависимости — его не касается. pnpm выбран под монорепо из двух пакетов: строгие `node_modules` не дают сайту случайно импортировать зависимость, объявленную у приложения.

## Особенность 1: дев и релиз делят папку данных

`app_data_dir()` определяется bundle identifier, и отладочная сборка использует тот же, что установленная. Значит, эксперименты в разработке пишут в **тот же реестр инстансов**, которым вы пользуетесь всерьёз.

Лечится штатным механизмом: `--config` сливает конфиги по правилам JSON Merge Patch, и `identifier` в их числе. `src-tauri/tauri.dev.conf.json` с отдельным идентификатором, подмешанный в дев-скрипте, даёт дев-приложению свою папку данных.

**Делаем в Фазе 1**, вместе с реестром: пока хранить нечего — терять тоже нечего.

## Особенность 2: правка Rust убивает запущенный ComfyUI

Следствие решения из раздела про `supervise/`: процессы живут в Job Object с `KILL_ON_JOB_CLOSE`, чтобы падение приложения не оставляло python-сирот с занятой видеопамятью. Тот же механизм срабатывает при перезапуске окна после пересборки Rust.

Цена конкретная: холодный старт реальной сборки с полусотней кастомных нод — до пяти минут. Одна правка в `supervise/windows.rs` означает пять минут ожидания ради одной строчки.

**Делаем в Фазе 2**, до работы над супервизором: раньше не нужно, позже — поздно.

## Стенд

Поддельный инстанс, который выглядит для приложения настоящей портабл-сборкой, но стартует за секунду. `tools/fixtures/fake-instance/`:

```
python_embeded/     ← junction на системную установку Python
ComfyUI/
  main.py           ← заглушка сервера
  comfyui_version.py
run_nvidia_gpu.bat
run_cpu.bat
advanced/run_nvidia_gpu_disable_api_nodes.bat
```

`python_embeded` — **каталоговый junction** на системный Python: на Windows не требует прав администратора, создаётся мгновенно, не занимает места, а `python_embeded\python.exe` при этом существует и запускается. Валидация папки и запуск интерпретатора работают по-настоящему, а не в обход. Junction нельзя положить в git, поэтому фикстура создаётся скриптом.

`.bat` пишутся однострочниками того же вида, что в настоящей сборке, включая вариант с путями `..\` в `advanced\` — иначе парсер профилей не на чем проверять.

Заглушка `main.py` воспроизводит всё, на что смотрит супервизор: печатает в **stderr** строки старта с задержками, среди них строки с `\r` (иначе замену последней строки не проверить), поднимает `/system_stats` через заданное число секунд, уважает `--port` и `--disable-auto-launch`, отдаёт `/object_info` с выдуманными нодами и принимает `/userdata`.

Режимы задаются аргументами, каждый отвечает сценарию из `specs/`:

| Режим | Что проверяет |
|---|---|
| Старт за 2 секунды | Штатный путь |
| Долгий старт | Что ожидание готовности не обрывается раньше времени |
| Выход с ошибкой | Аварийное завершение, `US-RUN-06` |
| Зависание без ответа | Таймаут готовности |
| Самоперезапуск | Перезапуск сервера извне, `US-RUN-07` |
| Занятый порт | Выдача следующего свободного, `US-RUN-02/AC-7` |

**Чего стенд не заменяет:** отсутствия 403 у дочернего вебвью, перетаскивания картинок на холст, внешних ссылок, реального самоперезапуска от ComfyUI-Manager, настоящих категорий моделей. Это редкие проверки, а не ежедневные.

## Браузерный контур — отложен

Фронт можно поднимать отдельно и открывать в обычном браузере, но выгода меньше, чем кажется: горячая замена работает и в полном приложении. Реальных плюсов три — не нужен Rust-тулчейн, окно поднимается мгновенно, удобно ставить макет из `design/` рядом с живым экраном. Цена — слой заглушек для сгенерированных биндингов и набор фикстур. Решаем, когда появятся первые экраны.
