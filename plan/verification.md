# Верификация

> Раздел плана. Оглавление — [PLAN.md](../PLAN.md).

Проверки ниже — инженерные: они подтверждают, что механика работает. Пользовательские тест-кейсы из них не выводятся и не должны писаться заново: их источник — критерии приёмки в `specs/`, где для каждого сценария уже перечислены наблюдаемые результаты, включая негативные случаи.

Тестовый стенд — реальная инсталляция `d:\program_files\comfyui\ComfyUI_windows_portable_nvidia\ComfyUI_windows_portable`.

1. `pnpm dev:desktop` → добавить папку → в списке профилей появились `run_nvidia_gpu`, `run_nvidia_gpu_fast_fp16_accumulation`, `run_cpu`, `advanced/run_nvidia_gpu_disable_api_nodes` с верно раскрытыми `..\` путями.
2. Запустить `run_nvidia_gpu` → **браузер не открывается**, логи текут в течение 5 секунд после старта, прогрессбары загрузки моделей не спамят буфер.
3. По готовности ComfyUI рисуется внутри окна, в консоли нет 403.
4. Перетащить PNG с воркфлоу на канвас → воркфлоу загрузился (проверка `disable_drag_drop_handler()`).
5. Кликнуть внешнюю ссылку в интерфейсе ComfyUI → открылся системный браузер, не webview.
6. Ресайз окна и сворачивание рейла → webview следует за областью контента без разрывов.
7. Stop → `python.exe` исчез из диспетчера задач, порт освободился.
8. **Тест Job Object:** снять наше приложение через диспетчер задач при работающем сервере → `python.exe` должен умереть следом.
9. Запустить два инстанса одновременно → разные порты, обе вкладки живые, переключение работает.
10. **Проверка швов:** `rg 'taskkill|JOB_OBJECT|CREATE_NO_WINDOW|python_embeded|\.bat' apps/desktop/src-tauri/src` не даёт совпадений вне `supervise/windows.rs` и `discovery/windows_portable.rs`.
11. **Проверка развязки пакетов:** `pnpm dev:docs` поднимает сайт и `pnpm build:docs` собирается при заведомо сломанной Rust-части — значит, зависимости между пакетами действительно нет.

## Общие модели

Проверяем не глазами по UI, а через API самого ComfyUI.

12. Запустить инстанс с включёнными общими моделями → `GET http://127.0.0.1:<port>/internal/folder_paths` содержит пути из общего корня, и при `is_default: true` общий путь стоит **первым** в массиве своей категории.
13. В консоли старта видны строки `Adding extra search path checkpoints D:\…` — `utils/extra_config.py:33` логирует каждый добавленный путь, наш стриминг логов их покажет.
14. Модель, лежащая **только** в общей папке, появляется в дропдауне ноды Load Checkpoint.
15. Локальные модели инстанса при этом никуда не делись — проверка аддитивности `add_model_folder_path`.
16. Режим «файл в инстансе» поверх уже существующего чужого `extra_model_paths.yaml` → создан `.bak-<timestamp>`, оригинал не потерян, без подтверждения ничего не перезаписано.
17. В сгенерированном YAML нет ключа `custom_nodes` ни при каких подпапках общего корня — в том числе когда `custom_nodes\` в нём реально лежит.
18. Выключить общие модели → рестарт → `/internal/folder_paths` вернулся к локальным путям.
19. Указать несуществующий или отключённый корень → предупреждение **перед** стартом, а не «model not found» посреди работы.

## Библиотека воркфлоу

20. Добавить воркфлоу в запущенный инстанс → он появляется в `GET /v2/userdata?path=workflows` и виден в браузере воркфлоу после рефреша.
21. Повторное добавление того же имени → 409 и диалог, а не тихая перезапись.
22. Добавление в остановленный инстанс, у которого в профиле стоит `--user-directory` → файл лёг в указанную папку, а не в дефолтную.
23. Воркфлоу с заведомо отсутствующей нодой → предупреждение со списком, добавление при этом не заблокировано.
24. Удалить папку библиотеки при открытом приложении → «библиотека недоступна», приложение живо.
25. Положить JSON в папку библиотеки мимо приложения → он появляется в списке, без записи в манифесте.
25а. Окно закрыто на «Настройках → Библиотека воркфлоу» и открыто заново → раздел тот же. Старый адрес `#/workflows` из сохранённого состояния уводит туда же, а не в пустоту.
25б. Скопировать JSON воркфлоу в буфер, нажать «Вставить из буфера» → поле заполнилось само, показано число узлов. Отказ webview читать буфер оставляет поле пустым и Ctrl+V рабочим — ошибки нет.
25в. Вставить не воркфлоу (любой другой JSON) → «Сохранить» недоступно, файл не создан. Вставить с именем, которое в библиотеке уже занято → отказ под полем имени, файл не тронут.

## Деинсталляция — главный тест требования

26. Установить, добавить инстанс, настроить общие модели и библиотеку, удалить через «Установка и удаление программ» **с галкой** → `%APPDATA%\<identifier>` и `%LOCALAPPDATA%\<identifier>` исчезли; папка моделей, библиотека воркфлоу и сами инстансы на месте.
27. То же **без галки** → данные сохранены, повторная установка видит прежний реестр инстансов.
28. Установка новой версии поверх старой → данные не тронуты (в update-режиме очистка не выполняется).
29. После удаления с галкой пройтись поиском по `%APPDATA%`, `%LOCALAPPDATA%`, `Documents` — следов приложения нет.

30. Тег, не совпадающий с версией в `tauri.conf.json`, роняет сборку до её начала.

32. В опубликованном релизе лежат инсталлятор, `.sig`, `latest.json` и `SHA256SUMS.txt`; сумма совпадает со скачанным файлом.
33. Тег с дефисом даёт предрелиз, и `releases/latest` его не показывает.
34. Кнопка на сайте ведёт на инсталлятор именно той версии, что указана рядом.
35. Сборка сайта проходит при недоступном GitHub API — с запасной ссылкой вместо подробностей.
36. После публикации релиза сайт обновляется без ручного вмешательства.
37. Установка на чистой машине: предупреждение SmartScreen выглядит так, как описано на странице документации.
38. Приложение находит новую версию и не ставит её без согласия.
39. При работающем инстансе установка не начинается молча — предложен выбор, и он соблюдается.
40. После обновления настройки и реестр инстансов на месте.
41. Без сети приложение работает и не показывает ошибок проверки обновлений.
42. Подменённый файл обновления не устанавливается — подпись не сходится.

## Тема и язык

30. Переключение светлая / тёмная / системная без перезагрузки; в системном режиме интерфейс следует за сменой темы Windows на лету.
31. Титлбар перекрашивается вместе с интерфейсом.
32. Ни один токен не остался неопределённым — пройти все три состояния темы по каждому экрану.
33. Переключение языка без перезагрузки, атрибут `<html lang>` обновился.
34. `pnpm i18n:check` падает и когда ключ из `ru.json` удалён, и когда добавлен лишний.
35. Русская плюрализация: 1 инстанс / 2 инстанса / 5 инстансов.
36. Китайский не ломает вёрстку рейла, глифы рендерятся шрифтом с CJK-покрытием, а не фолбэком.
37. Испанский — прогон по самым длинным строкам: кнопки и таблицы не разъезжаются.
38. Ошибка из Rust переводится во всех четырёх локалях; выдуманный код показывается как код, интерфейс жив.

## Уведомления и прогресс

39. Успешное добавление инстанса → тост, автоскрытие примерно через 4 секунды.
40. Ошибка записи `extra_model_paths.yaml` → тост висит до закрытия, детали разворачиваются, копирование работает.
41. Падение процесса при открытой вкладке ComfyUI → тоста нет, статус в рейле сменился, запись есть в консоли инстанса.
42. Скан общей папки на сотни гигабайт → индетерминантный индикатор, интерфейс не подвисает.

44. Сворачивание рейла → вебвью следует за контентной областью без разрывов и наездов.

54. Установка новой версии рядом со старой → обе в реестре, в карточке каждой виден исходный архив.
55. Инстанс из мастера сразу подключён к общим моделям и библиотеке, если тумблеры были включены.
