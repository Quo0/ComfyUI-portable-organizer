# Выпуск

> Раздел плана. Оглавление — [PLAN.md](../PLAN.md).

Артефакты живут в GitHub Releases, сайт документации ссылается на них кнопкой «Скачать». Репозиторий публичный — иначе ассеты не скачать без авторизации, а Pages требуют платного тарифа.

## Версия — единственный источник

`src-tauri/tauri.conf.json`, поле `version`. Тег обязан совпадать, и первым шагом воркфлоу это сверяется: `v<version>` против имени тега, расхождение роняет сборку. Без такой проверки однажды выйдет релиз, где тег говорит одно, а приложение показывает другое, и понять, что установлено у пользователя, станет невозможно.

## Воркфлоу `release-desktop.yml`

Триггер — пуш тега `v*`, раннер `windows-latest`.

Порядок: сверка тега с версией → Node и pnpm → Rust с кэшем Cargo → `pnpm install` → **ворота качества** → `tauri-apps/tauri-action`.

Ворота — это `pnpm design:check`, `pnpm i18n:check` и проверка типов. Стоят до сборки намеренно: опубликованный инсталлятор с рассыпавшейся тёмной темой или недостающим переводом откатывать дороже, чем не выпускать.

`tauri-action` создаёт релиз **черновиком**. Следующий шаг считает SHA-256 и дописывает суммы в тело релиза, и только после этого черновик публикуется — так не бывает состояния, когда файл уже виден, а контрольной суммы ещё нет.

Тег с дефисом (`v0.2.0-beta.1`) помечается предрелизом. Тогда `releases/latest` его пропускает, и кнопка на сайте продолжает вести на стабильную версию.

Тело релиза берётся из секции `CHANGELOG.md` для этой версии.

## Состав релиза

| Файл | Зачем |
|---|---|
| `...-setup.exe` | Инсталлятор NSIS, установка в профиль пользователя |
| `...-setup.exe.sig` | Подпись обновления |
| `latest.json` | Манифест для апдейтера |
| `SHA256SUMS.txt` | Проверка целостности вручную |

Контрольные суммы здесь важнее обычного: приложение неподписанное, и сверка суммы — единственный доступный пользователю способ убедиться, что файл не подменили.

## Кнопка «Скачать» на сайте

Ссылка не пишется руками и не добывается запросом из браузера. VitePress выполняет загрузчики данных во время сборки: `download.data.ts` спрашивает у GitHub API последний непредрелизный выпуск и отдаёт версию, ссылку, размер, дату и контрольную сумму. Всё попадает в статику — на странице не остаётся ни одного сетевого запроса.

**Сборка сайта не должна падать из-за GitHub.** При недоступном API или исчерпанном лимите запросов загрузчик возвращает запасной вариант — ссылку на страницу релизов без подробностей. Сайт публикуется всегда.

**Сайт пересобирается по публикации релиза**: воркфлоу выпуска в конце дёргает деплой документации. Иначе кнопка отставала бы до следующей правки доков.

Рядом с кнопкой — версия, дата, размер, контрольная сумма и ссылка на все версии: пользователь должен видеть, что качает, до клика.

## Подписи нет, и это надо объяснить

Azure Trusted Signing — самый дешёвый путь — доступен только организациям и самозанятым из США и Канады. Обычный OV-сертификат стоит сотни долларов в год и всё равно требует накопления репутации, прежде чем SmartScreen успокоится. Решение: раздавать без подписи.

Отсюда обязательная страница `guide/smartscreen`: как выглядит предупреждение «Windows защитила ваш компьютер», почему оно появляется, что нажать, как сверить контрольную сумму, и прямое признание, что подписи нет. Ссылка на неё стоит рядом с кнопкой скачивания, а не прячется в глубине документации: без объяснения заметная часть людей решит, что скачала вирус.

## Автообновление

Три требования Tauri v2, каждое легко пропустить: `bundle.createUpdaterArtifacts: true`, пара ключей от `tauri signer generate` (публичный в `plugins.updater.pubkey`, приватный и пароль — в секреты CI), и поле `signature` в `latest.json`, которое содержит **содержимое** `.sig`, а не путь к нему.

**Приватный ключ хранится вне репозитория и резервируется.** При его утере выпустить обновление для уже установленных копий будет невозможно никогда.

**Подпись обновлений — не подпись кода.** Ключи minisign доказывают, что обновление выпустили вы; на SmartScreen они не влияют. Механизмы разные.

**Обновление никогда не ставится молча — и вот почему это критично.** На Windows приложение принудительно закрывается во время установки: таково ограничение инсталлятора. А дочерние процессы у нас живут в Job Object с `KILL_ON_JOB_CLOSE`. Складываем: пользователь генерирует картинку, соглашается на обновление — и ComfyUI умирает вместе с очередью, а следующий холодный старт займёт минуты.

Поэтому перед установкой приложение смотрит, есть ли работающие инстансы, и при наличии предлагает выбор: остановить их и обновиться либо отложить установку до следующего запуска.

**Проверка обновлений отключаема.** Она единственное, что приложение отправляет наружу, и это оговорено отдельным исключением в `NFR-350`.
